## Goal
The **Picture settings** screen of the dashboard shows the form of Part 7u under the read only list, filled with the values of `config/images.json`. The person can type and see the sentences, the changes and the new file text. There is no save.

## Why it matters
The owner can now try the form in the real dashboard. Nothing can be broken, because nothing is written. The save waits for decision 24 (the write mode).

## Steps
1. `app.js`: import `imagesFormScreen`; `imagesView` keeps the text of the file and shows the form (with the heading "Try a change") under the read only screen. A missing or bad file starts the form from the shipped values; the note above already says why. The late-answer guard stays. No write call.
2. `admin-images-form.test.ts` (11 tests, the real dashboard in jsdom with a fake GitHub): the form is there once, under the screen, filled from the file; a missing or bad file; a good edit; a wrong edit; unknown keys kept; the screen above is not changed by typing; no button, link or form tag; an editor sees no form; a late answer; opening twice; the code has no write call. `images-form-screen.test.ts`: the case "nobody calls it" now says "only app.js calls it".
3. Seven deliberate mistakes.
4. `AI_OPERATIONS.md` Section 13 (coverage row), version, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- An admin sees the form under the list; typing shows changes or a sentence; nothing is sent to GitHub.
- An editor sees neither the menu item nor the form.
