## Goal
The build stops when a link opens a new tab without `rel="noopener"` (or `noreferrer`), and warns when such a link does not tell the reader it opens a new tab.

## Why it matters
A page opened with `target="_blank"` and no `noopener` could control the page that opened it (older browsers). Screen reader users must be told before a link moves them to a new tab. Today's footer links are correct; the check keeps every later link, post or page correct too.

## Steps
1. New `site/scripts/new-tab-lib.mjs` with `checkNewTabLinks(html)`.
2. `site/scripts/validate-html.mjs`: run it on every built page.
3. New test `new-tab.test.ts` (35 cases, with a fake dist folder run of the real gate and a read of the real footer).
4. Run the gate on today's real build, then on throw away copies with the real build broken.
5. Version 0.101.118, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A link with `target="_blank"` and no `noopener` or `noreferrer`, and a `base` tag with a new tab target, fail the gate.
- A safe link that never says "new tab" only warns.
