## Goal
A category and an author can have their own search title and search description (`metaTitle`, `metaDescription`), the page head uses them, and saving in the dashboard never loses them.

## Why it matters
Part 6 puts the Search engine listing box on more screens. This first small part builds the data and the rules, as Part 5a did for the post box, so the screens of the next part have something real to show.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 33.2 and the code of Parts 5a and 5b.
2. Add `listingHead` to `seo.ts`, the two category helpers, the two author fields in the schema, and pass them through `Listing.astro` and the two pages.
3. Add `entryErrors` and `mergeEntry` to `listing.js`; use them in the Categories and Authors saves of `app.js`.
4. Write the tests, make deliberate mistakes to prove they fail, build once with real values.
5. Bump the version, write the changelog, update `CODING_PLAN.md` and `INCOMPLETE.md` (`VERSIONING.md`).

- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- A category with `metaTitle` and `metaDescription` shows them in `<title>` and `<meta name="description">`; the heading on the page stays the display name.
