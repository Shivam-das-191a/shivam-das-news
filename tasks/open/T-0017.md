## Goal
The post editor's Search engine listing box has a "Hide this page from search engines" switch. On sets `robots: noindex,follow`; off sets `index,follow`. A red note shows when a Breaking or Featured post is hidden. Only editors and admins may use it, and Save checks the role again.

## Why it matters
A page that should not be listed (a thin, test or sensitive page) can be hidden in one tick, without knowing what a robots tag is. The build already leaves a noindex post out of the sitemaps, the news sitemap and push announcements, so the switch only has to write the right value.

## Steps
1. Read `LOGICS.md` Section 21 (`hideFromSearch`) and `NEWS_WEBSITE_PLAN.md` 33.2.
2. Add the action `post:noindex` for admin and editor in `site/public/admin/js/roles.js`.
3. Add the switch, the "what it removes" text and the red note to `listing-box.js` (new options `canHide` and `onHide`, new export `isHidden`).
4. Wire it in `app.js`: write `d.robots` through `hideFromSearch()`, keep the Robots list in step, lock the Robots list for other roles, refuse Save when a role without the right changes robots.
5. Add the styles; write the tests; make deliberate mistakes to prove they fail.
6. Bump the version, write the changelog, tick Part 4 in `CODING_PLAN.md`, update `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- The switch and the Robots list always show the same state; the saved file has `robots: "noindex,follow"` when on and `index,follow` when off.
- A writer cannot change robots, not even through a restored draft.
