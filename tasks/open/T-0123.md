## Goal
The build stops when a page has a `tabindex` that is not a whole number or is above 0; it warns on an `accesskey` and on an `onclick` on a plain tag with no role.

## Why it matters
A tabindex above 0 makes a reader with a keyboard jump around the page in a strange order. An accesskey clashes with the shortcuts of browsers and screen readers. A post written by the owner can bring hand typed HTML.

## Steps
1. New `site/scripts/tabindex-check-lib.mjs` with `checkTabindex(html)`.
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `tabindex-check.test.ts` (25 cases, with a fake dist folder run of the real gate and a read of every template).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with a bad word added.
5. Version 0.101.125, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- `tabindex="3"` and `tabindex="abc"` fail the gate.
- An `accesskey` only warns.
