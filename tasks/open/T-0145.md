## Goal
The build stops when an attribute that points to another element by its id points to an id that is not on the page (`headers`, `list`, `form`, `for` of an output, `popovertarget`); it warns when the target is the wrong kind of element.

## Why it matters
The browser quietly ignores these: the cell has no header, the field shows no suggestions, the field is never sent and the button does nothing. The dashboard preview shows nothing wrong. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry them.

## Steps
1. New `site/scripts/ref-check-lib.mjs` with `checkRefs(html)` (two steps over all tags: first the ids, then the attributes that point to an id; comments, script, style and template skipped).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `ref-check.test.ts` (49 cases, with a fake dist folder run of the real gate and a read of the base layout and the post card).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.147, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A `<button popovertarget="menu">` with no element `id="menu"` fails the gate and names the page.
- A `popovertarget` that points to an element with no `popover` attribute only warns.
