## Goal
The build stops when a built page has no `lang` on the html tag, no viewport meta, no skip link to `#main`, no element with id `main`, not exactly one `main`, no header or no footer.

## Why it matters
POLISH (Accessibility and Mobile) lists the skip link, the landmarks and a page that fits a phone. The templates do it today, but nothing kept it that way when someone changes `Base.astro`.

## Steps
1. New `page-basics-lib.mjs` with `checkPageBasics`.
2. `validate-html.mjs`: call it for every built page (errors stop the build, warnings are printed).
3. New test `page-basics.test.ts`; the fake pages of `img-check.test.ts`, `img-priority.test.ts` and `img-ratio.test.ts` get a proper page shell.
4. Deliberate mistakes, one at a time.
5. Version 0.101.104, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A page without lang, viewport, skip link, id main, one main, header or footer fails the gate; a good page passes; two navs with one unlabelled only warn.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card).
- Check: `npm test`: 193 files and 4079 tests passed (before: 192 and 4059). `npm run build` ended with `Validation passed.` on today's content. The first run of the three older gate tests FAILED (their fake pages had no lang, skip link or main); the fake pages got a proper shell (the code was right, the old pages were incomplete).
- Deliberate mistakes: twelve made one at a time (lang as a warning, viewport not checked, skip class ignored, id main any, one main loosened, footer unchecked, header unchecked, script not skipped, nav limit, aria-labelledby ignored, href not exact, lang not trimmed). Eleven were caught at once; "href not exact" was NOT caught, so one test was added (`/main/` and `#mainly`) and it was caught.
- Not verified live: no GitHub run of the validate workflow yet.
