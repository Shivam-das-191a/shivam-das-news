## Goal
The build stops when a `target` or `formtarget` starts with an underscore but is not `_blank`, `_self`, `_parent` or `_top` (`_blnk`, `_new`), or is one of those words with a space around it; it warns when the target is the plain word `blank`, `self`, `parent`, `top` or `new` with no underscore.

## Why it matters
`<a target="_blnk">` looks like "open in a new tab" but the browser opens a window with that odd name and every such link reuses it; `target=" _blank"` is read with the space, so it is not `_blank` either. The dashboard preview shows nothing wrong. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry them.

## Steps
1. New `site/scripts/target-check-lib.mjs` with `checkTargets(html)` (one pass over all tags; comments, script, style and template skipped).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `target-check.test.ts` (44 cases, with a fake dist folder run of the real gate and a read of the footer, the base layout, the post card and the contact form).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.149, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A `<a target="_blnk">` fails the gate and names the page.
- A `<a target="blank">` only warns.
