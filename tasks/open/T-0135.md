## Goal
The build stops when a built page opens a block tag (a div, a list, a table, a heading, a figure and the like) while a `<p>` is still open; it warns on a block tag or a `<p>` directly inside an inline tag or a heading.

## Why it matters
HTML does not allow a block inside a paragraph. The browser closes the paragraph early and leaves an empty paragraph after the old end tag, so the page shows extra space and a screen reader reads the text as two paragraphs. A post written by hand (PLAN 37) or an old Blogger post (PLAN 11) can wrap a `<div>` or a list in a `<p>`, and the owner cannot see the extra empty paragraph in the dashboard preview.

## Steps
1. New `site/scripts/paragraph-check-lib.mjs` with `checkParagraphs(html)` (a small tag stack that follows the browser rule: a block tag closes an open paragraph, a button, a table cell and an earlier list item stop the search).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `paragraph-check.test.ts` (56 cases, with a fake dist folder run of the real gate and a read of the real base layout and ten real components).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.137, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A `<div>` and a `<ul>` inside a `<p>` fail the gate.
- A `<div>` directly inside a `<span>` only warns.
