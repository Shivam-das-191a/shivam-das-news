## Goal
One plain function builds the whole rename of a picture: the new name is checked, every file that names the picture gets the new address, the old address gets a 301, and the alt text, caption and credit move with the file.

## Why it matters
PLAN 33.3 says a rename keeps the old address working and updates the posts in the same commit. The Rename screen (next part) can only be safe if these rules are tested first, without a screen.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 33.3, `public/admin/js/media-meta.js`, `public/admin/js/category-rename.js` and `src/lib/redirects.ts`.
2. Write `public/admin/js/file-rename.js` (`checkNewName`, `planFileRename`); nothing in the dashboard calls it yet.
3. Make `usedIn` and the new rule use one shared pattern (`pathPattern` in `media-meta.js`).
4. Write the tests, make deliberate mistakes, run the whole suite and the build.
5. Bump the version, write the changelog, update `CODING_PLAN.md` and `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- A new name with capitals, spaces, another ending, a folder, an existing name or the old name is refused with a plain message.
- The plan names the new address in every file that used the old one, adds one 301, never writes a loop or a chain, stops at the 2000 redirect limit, and moves the `config/media.json` entry.
- A picture mentioned at the end of a sentence ("see /media/a.webp.") counts as used.
