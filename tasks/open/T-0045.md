## Goal
`site/public/admin/js/hosting-result.js` has `buildResultList(run)`, `confirmFor(list, confirmed, o)`, `carryOver(run)` and `shortUrl(url)`: the data of the result list that follows `hostPost`. One row for each picture with a label, a plain sentence and one action (Retry, Confirm, Replace or none), the addresses for Retry and Confirm, one headline, and the two helpers the buttons need. Pure: no screen, no network, no storage.

## Why it matters
Without it the screen would have to decide by itself which failures can be tried again, which pictures wait for the writer, and what the next run starts from. Written once and tested here, the screen (the next part) only draws. Nothing calls it yet, so the live site and the dashboard do not change.

## Steps
1. Read `hosting-run.js` (`items`, `REASONS`, `explain`) and `hosting-plan.js` (`summarize`), `hosted-meta.js` (`needsConfirm`, `RIGHTS_NOTICE`).
2. Write `hosting-result.js`: `RETRYABLE`, `LABELS`, `TONES`, `shortUrl`, `buildResultList`, `confirmFor`, `carryOver`.
3. Write `site/tests/unit/hosting-result.test.ts`: every row type, every reason word, the counts and lists, the headline, bad input, and the real `hostPost` for Retry and Confirm.
4. Make deliberate mistakes and see the tests fail.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- A failed picture gets Retry only when trying again can help; a refused picture never gets Retry or Confirm; Confirm works only for pictures that wait for it.
- After `carryOver`, the next `hostPost` asks the service only for the pictures that are still outside.
- The input is never changed, and bad input gives an empty list, not an error.
