## Goal
The build stops on an inline `<svg>` that holds a script, loads a picture from `http://` or says `role="img"` with no name; it warns on the other SVG problems.

## Why it matters
Every icon of this site is an inline SVG (PLAN 29.3). A picture that carries meaning needs a name for a screen reader, a decoration must be hidden from it, and a script or an `http://` picture inside an SVG breaks the security rules of this site (`site/public/_headers`). Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry any of these, and the dashboard preview shows nothing wrong.

## Steps
1. New `site/scripts/svg-check-lib.mjs` with `checkSvg(html)` (one pass over the svg, use, image, foreignObject, script and title tags; comments, style and template skipped; only the outer svg is judged).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `svg-check.test.ts` (57 cases, with a fake dist folder run of the real gate and a read of the icon component and the base layout).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.142, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A script inside an svg, an svg image from `http://` and an `<svg role="img">` with no name fail the gate.
- An svg with no name that is not hidden only warns.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card). Nothing in `site/src/`, `site/config/` or `site/content/` changed.
