## Goal
The dashboard has a new menu item, **Picture settings** (admins only, address `#/images`), that opens the read only screen of Part 7r with the values of `config/images.json`.

## Why it matters
The owner can now look at the eleven picture settings inside the dashboard, and see which ones the code already uses, before any form can change a file.

## Steps
1. `app.js`: import `imagesScreen` and `imagesPathOf`; add the menu item before Settings (role `settings`, so admins only); add the route `#/images`; add `imagesView` (reads the file with `getText` only; a missing file, bad JSON or a value that is not an object shows the shipped values and one plain sentence; if the person has gone to another screen while the file loads, nothing is drawn).
2. `images-screen.js`: only the header comment changes. `images-screen.test.ts`: the test "nobody calls it" now says "only app.js calls it".
3. `admin-images-screen.test.ts` (9 tests): menu item and title, values from the file, missing file, four bad files, a wrong value inside a good file, an editor cannot open it, nothing is written, a late answer does not draw over another screen, the whole menu order, the new code has no write call.
4. Six deliberate mistakes.
5. `AI_OPERATIONS.md` Section 13 (menu list and coverage table), version, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- An admin sees **Picture settings** in the menu and eleven rows; an editor does not see the item and gets one plain sentence if they type the address.
- Nothing is written to GitHub by the screen.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 178 files and 3583 passed (before: 177 files and 3574), build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (85 cards). The budget warning is the old one (CHANGELOG, INCOMPLETE; decision 43).
