## Goal
The build stops when a built page loads Flash (an `<object>`, `<embed>` or `<param>` for it) or an `<object>` or `<embed>` from `http://`; it warns on any other `<object>` or `<embed>`.

## Why it matters
Flash no longer runs in any browser, so such a page shows an empty box. The security rules of this site (`site/public/_headers`) say `object-src 'none'`, so every other `<object>` and `<embed>` is blocked once the rules are enforced. Old Blogger posts (XML import) still carry these tags and the dashboard preview shows nothing wrong.

## Steps
1. New `site/scripts/object-check-lib.mjs` with `checkObjects(html)` (one pass over the object, embed and param tags, comments, script, style and template skipped).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `object-check.test.ts` (39 cases, with a fake dist folder run of the real gate and a read of the base layout).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.141, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A Flash embed, a Flash object and an object from `http://` fail the gate.
- A PDF embed only warns.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card). Nothing in `site/src/`, `site/config/` or `site/content/` changed.
- Check: `npm test`: 229 files and 5526 tests passed (before: 228 and 5487). `npm run build` ended with `Validation passed.` on today's real build with no new message (with `SITE_URL` set).
- Found while building: my first test of an old Blogger player (an `<object>` with a Flash `<param>` and a Flash `<embed>`) gave the Flash errors and also a plain warning for the outer `<object>`. The warning is now kept back on a page that already has a Flash error.
- Throw away copies of the real build in `/tmp` (not in the ZIP): a Flash `<embed>`, a Flash `<object>` (classid) and an `<object>` from `http://` each ended with exit code 1 and `Validation failed`; a PDF `<embed>` ended with exit code 0 and a warning.
- Not proved: no real story page exists (the only post is a draft), so an imported Blogger post with these tags was not read on a built story page.
- Not verified live: no GitHub run of the validate workflow yet.
