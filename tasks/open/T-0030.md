## Goal
A 301 from an old picture address to a new picture address survives the build, so a renamed file keeps its old address working.

## Why it matters
PLAN 33.3 says a rename keeps the old address working. The redirect builder dropped any redirect whose target was not a live page, and a picture was never one, so the rename in the next parts would have broken old links without any message.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 33.3, `src/lib/redirects.ts` and `src/pages/redirects-map.json.ts`.
2. Write `src/lib/media-live.ts` (`listMediaFiles`, `mediaUrls`).
3. Add the picture addresses to the live set in `redirects-map.json.ts`.
4. Write the tests, make deliberate mistakes, run a real build with a temporary picture and redirect, run the whole suite.
5. Bump the version, write the changelog, update `CODING_PLAN.md` and `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- A real build writes the 301 for a picture that exists and drops it, with a message, for a picture that does not; a picture that still exists is never redirected away.

## Evidence
- Tests: before this change `Test Files 131 passed (131), Tests 2458 passed (2458)`; after it `Test Files 132 passed (132), Tests 2471 passed (2471)`; 13 new tests in `site/tests/unit/media-live.test.ts`.
- Real build: `dist/_redirects` held `/media/2026/11/old.webp /media/2026/11/new.webp 301` with the picture present; the build log said "dropped ... which is not a live page" with the picture removed. Temporary files removed.
