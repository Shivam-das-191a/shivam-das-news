## Goal
The build stops when an iframe on a built page has no name, loads over `http://` or has a `javascript:`, `data:` or `vbscript:` address, and warns when it has no lazy loading, no size, no sandbox (frame from another website), a vague name, no scheme or no source.

## Why it matters
A screen reader reads a frame by its name; with none it says only "frame". An `http://` frame on an `https://` page is blocked by the browser, so the embed shows nothing. A post written by the owner can bring an HTML block with an embed (PLAN 37), so the check must exist before the first embed.

## Steps
1. New `site/scripts/iframe-check-lib.mjs` with `checkIframes(html, ownHosts)`.
2. `site/scripts/validate-html.mjs`: run it on every built page with the same own-host list as the picture check.
3. New test `iframe-check.test.ts` (44 cases, with a fake dist folder run of the real gate and a read of the real layout).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with an iframe added.
5. Version 0.101.120, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- An iframe with no name and an iframe on `http://` fail the gate.
- Lazy loading, size, sandbox and vague name only warn.
