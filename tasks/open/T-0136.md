## Goal
The build stops when a form of a built page sends to an `http://` address or holds a password field and sends with GET (the default when there is no method); it warns on a file field without `method="post"` and `enctype="multipart/form-data"`, a field with no name, a name used twice, a lone radio button and a select with no option.

## Why it matters
The browser reports none of these. A password in a GET form lands in the address bar and the browser history; a form that sends to `http://` is read on the way; a field with no name is never sent; a file field without multipart sends only the file name. A form written by hand (PLAN 37) must do what it says, and the owner cannot see these faults in the dashboard preview.

## Steps
1. New `site/scripts/form-behavior-check-lib.mjs` with `checkFormBehavior(html)` (one pass over the form, input, select, textarea and option tags).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `form-behavior-check.test.ts` (59 cases, with a fake dist folder run of the real gate and a read of five real templates).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.138, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A password field in a form with no method and a form with `action="http://..."` fail the gate.
- A field with no name only warns.

- Files changed: the paths of this card (new files: the library, the test and this card). Nothing in `site/src/`, `site/config/` or `site/content/` changed.
