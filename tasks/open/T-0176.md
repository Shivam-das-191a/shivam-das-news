## Goal
The build warns when the text of a built page has a word typed with Caps Lock on by mistake (`hELLO`, `cAPSLOCK`), and never stops the build for it.

## Why it matters
Text typed fast shows this slip when the Caps Lock key was on and Shift was held for the first letter. A reader sees each one at once and trusts the site a little less. No older check reads it.

## Steps
1. New `site/scripts/capslock-check-lib.mjs` with `checkCapsLockSlips(html)` (reads the title and the body text of every page; only the letters A to Z are read; an inline tag leaves no gap, a block tag, a `br` and a character reference end the run; comments and script, style, template, textarea, pre, code, kbd, samp, svg, noscript and select blocks skipped; attributes and the meta description not read; one message per page with a count and the first word; no errors).
2. The slip: a word of 5 or more letters whose first letter is small and whose other letters are all capital.
3. Left out: words of 4 letters or fewer (`mRNA`, `iOS`), a word with a small letter after the capitals (`iPhone`, `eBay`, `macOS`), a word joined to a letter, digit, underscore, dot, slash, at sign, hash sign, colon or hyphen, code, text in another script.
4. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
5. New test `capslock-check.test.ts` (70 cases, with a fake dist folder run of the real gate).
6. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with slips added.
7. Version 0.101.178, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A page with `wORLD` and `cAPSLOCK` gives one warning that names the page and counts 2 places; the build still passes.
- `mRNA`, `iOS`, `iPhone`, `#hELLO`, `me@hELLO.com`, text in `pre` or `code` and text in another script pass with no message.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card). Nothing in `site/src/`, `site/config/` or `site/content/` changed. No older test changed.
- Check: `npm test` (run in 3 shards): 266 files and 7627 tests passed (before: 265 and 7557). `npm run build` ended with `Validation passed.` on today's real build with no new message (with `SITE_URL` set).
- Throw away copy of the real build in `/tmp` (not in the ZIP): a paragraph with `wORLD`, `cAPSLOCK`, `mRNA` and `iOS` added to `index.html` gave one warning that named the page and counted 2 places, and the gate still ended with `Validation passed.`.
- Not verified live: no GitHub run of the validate workflow yet.

## If it goes wrong
Put back `validate-html.mjs` of v0.101.177 and delete the new library and its test.
