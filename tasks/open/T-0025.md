## Goal
The owner opens **Files** in the dashboard, finds a picture, writes its alt text, caption and credit, sees the image checks and where it is used, and saves them to `config/media.json`.

## Why it matters
Alt text was missing for most pictures and had no place to live. This screen is where the owner (or a writer) fills it in.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 33.3 and the rules of Part 7a.
2. Write `files-screen.js` on top of `media-meta.js` (add `featuredIn`).
3. Wire the route, the menu entry and `filesView` in `app.js`; Save checks the role and the limits again and writes with the file sha.
4. Write the jsdom tests, make deliberate mistakes, run the whole suite and the build.
5. Bump the version, write the changelog, update `CODING_PLAN.md` and `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- In a jsdom test: search, the only-without-alt switch, the editor, the checks, "Used in", a good save, a refused save and a read-only role all behave as described in the changelog.

Revert the commit; Cloudflare Pages, roll back to the previous deployment. The screen writes only `config/media.json`; delete the bad entry there to undo a saved detail. Nothing on the live site reads that file yet.
