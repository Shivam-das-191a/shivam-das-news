## Goal
`site/public/admin/js/hosting-plan.js` does the two pure jobs of the Save pipeline: `planHosting` (before any download: fetch, reuse, needs_confirm or refused for each outside picture, in the order of LOGICS 22) and `rewritePost` (after the pictures are hosted: the addresses in the body, `image` and `ogImage` become the new `/media/...` addresses). `summarize` gives the counts and the Retry list.

## Why it matters
This is the first slice of Part 3 (the pipeline in the dashboard). It needs no decision of the owner and no network, so it is done and tested alone. The rewrite is the risky step (a wrong replace would damage a post), so it has the most tests. Nothing calls it yet, so the live site and the dashboard do not change.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 34.3, `LOGICS.md` 22, `hotlink.js` (T-0036), `hosted-meta.js` (T-0039).
2. Export `absoluteUrl` and `maskCode` from `hotlink.js` (they were private); no other change there.
3. Write `hosting-plan.js`: `planHosting`, `summarize`, `rewriteUrls`, `rewritePost`.
4. Write `site/tests/unit/hosting-plan.test.ts`.
5. Make deliberate mistakes and see the tests fail; restore the code.
6. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged (the 74 tests of `hotlink.test.ts` still pass).
- The plan puts refused before needs_confirm before reuse before fetch; a different query string is a different picture; a picture used twice is planned once.
- The rewrite changes only the exact address (not a longer address that starts the same, not an address that merely contains the name, not text inside code), also the `&amp;` and `//host` forms and a proxy address that contains another address; the input is not changed; a failed picture stays as it was.
- After plan, host and rewrite, a second plan finds nothing left to host.
