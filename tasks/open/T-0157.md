## Goal
The build stops when a page has a `javascript:`, `file:` or `data:` address in `action`, `formaction`, `cite`, `ping`, `poster` or `longdesc` (`data:` is fine in a poster), or a `formaction` to `http://`; it warns on a `ping` to `http://` and on these attributes on a tag that ignores them.

## Why it matters
A `javascript:` address in a `formaction` runs code when the button is pressed, and a `file:` address points to the reader's own disk. An attribute on a tag that ignores it does nothing and no message shows. A snippet pasted by hand (PLAN 37) or an old Blogger post can carry these. `href` and `src` had checks; these six attributes did not.

## Steps
1. New `site/scripts/url-attr-check-lib.mjs` with `checkUrlAttrs(html)` (comments, script, style and template blocks skipped).
2. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
3. New test `url-attr-check.test.ts` (42 cases, with a fake dist folder run of the real gate).
4. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with bad markup added.
5. Version 0.101.159, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.
