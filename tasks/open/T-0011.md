## Goal
`npm run check:content` checks posts, pages, redirects and config files against the rules of LOGICS 23 and prints `CONTENT PASS` or `CONTENT FAIL` with one plain line per problem.

## Why it matters
A bad post (no image text, a wrong date, a lost redirect) can break the build or the site. This check finds it in a second, before the build, for the owner, an editor or an AI.

## Steps
1. Write `site/scripts/validate-content-lib.mjs` with the pure rules.
2. Write `site/scripts/validate-content.mjs` that reads the files, supports `--root`, `--base <ref>` and file names, and prints the result.
3. Write `site/tests/unit/validate-content.test.ts`, including a test that keeps `src/content.config.ts` and the script from drifting apart.
4. Add the script `check:content` and bump the version in `site/package.json` and the lock file; write the changelog and update the documents (`VERSIONING.md`).

## Done when
- A published post without `imageAlt`, a duplicate permalink, a changed address without a redirect, a removed config key and a token-like string each fail with a plain message.
- The real content of the repository prints `CONTENT PASS`.
- `npm test`, `npm run build` and `npm run preflight` pass, and preflight no longer skips the content step.
