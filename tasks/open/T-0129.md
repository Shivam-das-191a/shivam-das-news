## Goal
The build stops when `autocomplete` holds a word that is not a real field name, or when `inputmode`, `enterkeyhint`, `autocapitalize`, `spellcheck`, `translate`, `contenteditable`, `draggable` or the `wrap` of a textarea holds a value that is not real; it warns on `autocomplete="off"` on a password field.

## Why it matters
A browser never reports a typo such as `autocomplete="firstname"` (the real word is `given-name`) or `inputmode="number"` (the real word is `numeric`): it silently ignores it. The reader then gets the wrong phone keyboard, the password manager and the browser cannot fill the field, and everything is typed by hand. Forms and fields written by hand in a post or a custom block (PLAN 37) can carry these words.

## Steps
1. New `site/scripts/input-hints-lib.mjs` with `checkInputHints(html)`.
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `input-hints.test.ts` (45 cases, with a fake dist folder run of the real gate and a read of the real contact form and notifications page).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with a bad value added.
5. Version 0.101.131, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- `autocomplete="firstname"` and `inputmode="number"` fail the gate.
- `autocomplete="off"` on a password field only warns.
