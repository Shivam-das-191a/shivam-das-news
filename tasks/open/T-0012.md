## Goal
Every pull request and every push to `main`, `ai/` and `human/` branches runs the content check, the task check, the tests and the build, and shows red or green.

## Why it matters
A broken post stops the build and nothing new can be published. With this action a bad change is refused on the pull request, before it reaches `main`.

## Steps
1. Write `.github/workflows/validate.yml`: read-only, no secret, full history, Node 22, steps in a fixed order.
2. Pass every changing value (event, branch, base) through `env`, never inside a shell line.
3. Write `site/tests/unit/validate-workflow.test.ts` (12 tests, checks the file as text).
4. Bump the version, write the changelog and update the documents (`VERSIONING.md`).

## Done when
- `npm test` passes, including the 12 new tests, and the tests fail when the workflow is made unsafe (a write permission, a secret, an expression in a shell line, a wrong order).
- `npm run build`, `npm run check:content`, `npm run tasks:check` and `npm run preflight` pass.
- After merge, one pull request with a post that has no `imageAlt` shows a red run with a plain message, and a correct one shows green (owner or second key).

## If it goes wrong
Delete `.github/workflows/validate.yml`. The site and the other workflows are not affected.

## Stop and ask the owner if
- The workflow needs a secret or a changed permission in GitHub settings.
- Required status checks on `main` are to be switched on (the owner's setting).
