## Goal
The build stops when an input, select or textarea of a built page has no label: no label with text pointing to it or wrapping it, no aria-label and no aria-labelledby to an element of the page.

## Why it matters
POLISH (Accessibility) lists "Forms have labels and clear error messages". A field with only a placeholder is unnamed for a screen reader. The site does it right today (contact form, notification page), but nothing kept it that way when someone adds a form.

## Steps
1. New `form-labels-lib.mjs` with `checkFormLabels`.
2. `validate-html.mjs`: call it for every built page.
3. New test `form-labels.test.ts`.
4. Look at the real built pages first (all 21 fields of today's build), then run deliberate mistakes, one at a time.
5. Version 0.101.107, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A field with only a placeholder, an empty label, an aria-label that is empty and an aria-labelledby to a missing id each fail the gate; a good form passes; a label that points to a missing id only warns.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card).
- Check: `npm test`: 196 files and 4154 tests passed (before: 195 and 4126). `npm run build` ended with `Validation passed.` on today's real build (21 form fields on 2 pages, all named).
- Real page proof: one label taken out of the built contact page made the gate fail with `the form field input (type "email", name "email") has no label`; put back, it passed.
- Deliberate mistakes: twenty made one at a time in the library. Nineteen were caught at once; one was NOT (a `>` inside an attribute cutting a field tag short); a test line was added and all twenty are now caught.
- Not verified live: no GitHub run of the validate workflow yet.

## If it goes wrong
Put back `validate-html.mjs` of v0.101.106 and delete the library and the test.
