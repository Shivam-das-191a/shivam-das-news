## Goal
The build stops when a table cell has a `scope` that is not col, row, colgroup or rowgroup, or when a table marked `role="presentation"` or `none` holds a `th`; it warns when a table has no `th`, no caption or an empty `th`.

## Why it matters
A screen reader tells the reader which column and row a cell belongs to only from header cells. A post written by the owner can bring a table (PLAN 37 allows tables), so the check must exist before the first one.

## Steps
1. New `site/scripts/table-check-lib.mjs` with `checkTables(html)`.
2. `site/scripts/validate-html.mjs`: run it on every built page.
3. New test `table-check.test.ts` (35 cases, with a fake dist folder run of the real gate and a read of the real layout).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with a table added.
5. Version 0.101.121, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A wrong scope and a th in a layout table fail the gate.
- No th, no caption and an empty th only warn.
