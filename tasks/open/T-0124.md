## Goal
The build stops when a `<time>` has a `datetime` that is empty, is not a real value or is a date or time that does not exist; it warns on a `<time>` with no `datetime` whose text a machine cannot read.

## Why it matters
A news site shows a date on every story. A typed date such as `2026-02-30` or `19/11/2026` in `datetime` is silently ignored by search engines and reader tools. A post written by the owner can bring hand typed HTML.

## Steps
1. New `site/scripts/time-check-lib.mjs` with `checkTimes(html)` and `isValidDatetime(value)`.
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `time-check.test.ts` (31 cases, with a fake dist folder run of the real gate and a read of the real story template).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with a bad date added.
5. Version 0.101.126, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- `datetime="2026-02-30"` and `datetime="19/11/2026"` fail the gate.
- A `<time>` with words and no `datetime` only warns.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card). Nothing in `site/src/`, `site/config/` or `site/content/` changed.
- Check: `npm test`: 214 files and 4857 tests passed (before: 213 and 4826). `npm run build` ended with `Validation passed.` on today's real build with no new message (with `SITE_URL` set).
