## Goal
When `sizeWarnKb` in `site/config/images.json` is above 0, a picture of our own site that is shown inside the TEXT of a published post and is bigger than that many KB gives a WARNING in `npm run check:content`, like the top picture already does.

## Why it matters
Most of the weight of an article is in the pictures inside the text. The size warning of v0.101.71 only looked at the top picture and the share picture. It stays off (value 0) until the owner sets a number, so nothing changes today.

## Steps
1. `validate-content-lib.mjs`: `localPictures(body)` (Markdown and img, code skipped, one entry per file, no `..`), the call in `checkPost` for a published post, and one report per file in `tooBig`.
2. Tests (6 new cases, one runs the real script with 2, 5 and 0), then five deliberate mistakes.
3. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `sizeWarnKb` 0 or missing: the same result as v0.101.72. With a number: a WARN for each file in the text that is bigger, and still `CONTENT PASS`. A file used twice is reported once. A draft is never checked.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 164 files and 3446 tests passed, build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (70 cards).
- Deliberate mistakes: five made, five caught.
- Not verified live: no GitHub run of the validate workflow yet.

## If it goes wrong
Set `"sizeWarnKb": 0` in `site/config/images.json`. To remove the code, put back `validate-content-lib.mjs` of v0.101.72.

- The owner wants the size to be an error, or wants the pixel width checked (needs a way to read the picture size): each is its own part with its own decision.
