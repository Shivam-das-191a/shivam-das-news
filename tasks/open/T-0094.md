## Goal
When `site/config/images.json` has websites in `allowHosts`, the Save of the editor counts them as ours: a picture from such a website (exact name) is not fetched and not hosted. With an empty, missing, wrong or broken list nothing changes, and a name related to an agency or blocked website is ignored.

## Why it matters
The build check already accepts pictures from these websites (Part 7d), but the Save of the editor did not know the list, so it could still copy such a picture into the repository. Now the owner can mark a partner or own CDN website with no code change and no new secret. The shipped list is empty, so today nothing changes.

## Steps
1. `images-setting.js`: add `customAllowHosts` (the valid website names, or `undefined`); `hostingSettingsFromText` adds `allowHosts` to its answer only when there is a valid name.
2. `hosting-hook.js`: take `allowHosts` from the same one read (a list of the caller wins) and give it to `startHostingSave`.
3. `hosting-save.js`: give `allowHosts` to `hostingSetup`.
4. `hosting-setup.js`: add the websites to `ownHosts`, no repeat; ignore a name that is the same as, a sub name of or a parent name of an agency or blocked website.
5. `images-screen.js`: the row "Websites counted as ours" gets a new `use` word `buildSaveOwn`.
6. Tests: new `hosting-allow-hosts-save.test.ts` (39 cases); `images-screen.test.ts` changed to the new truth.
7. Fourteen deliberate mistakes.
8. Version, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With a website in `allowHosts` the Save makes no fetch and no picture commit for that website; an agency website or a blocked website in the list still waits or is refused; with every other text the Save works as before.
- No token or address is shown in any message.
