## Goal
The build stops when an on/off attribute is written as off (`disabled="false"`, `open="0"`, `hidden="no"`), because the browser still switches it on; it warns when the value is anything but nothing or the attribute's own name.

## Why it matters
An attribute of this kind is on whenever it is there, whatever its value says. A field with `disabled="false"` cannot be used, a `<details open="false">` is open, a `<script async="false">` is still async and a `<video autoplay="false">` still plays. The dashboard preview shows the same wrong page, so nobody sees the mistake. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry them.

## Steps
1. New `site/scripts/bool-check-lib.mjs` with `checkBools(html)` (one pass over all tags; comments, style and template skipped; the opening tag of a script is read, its text is not).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `bool-check.test.ts` (56 cases, with a fake dist folder run of the real gate and a read of the base layout, the post card and the contact form).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.148, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A `<details open="false">` fails the gate and names the page.
- A `<input disabled="true">` only warns.
