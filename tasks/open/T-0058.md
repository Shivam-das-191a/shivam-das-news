## Goal
The Files screen does not show a smaller copy (`name.480w.webp`) as a picture of its own, and a picture that has copies cannot be deleted, renamed or replaced from the screen until Part 4c-4b makes those three take the copies along.

## Why it matters
Copies are saved next to the picture (4c-3). If the screen showed them as pictures, the owner could delete or rename one and break a `srcset`. If delete, rename or replace touched only the main picture, copies would be left behind or would show the old picture. This part makes the screen safe before copies are ever switched on.

## Steps
1. Read `hosting-srcset.js` (`isVariantOf`, `variantsOnList`) and `files-screen.js`.
2. `files-screen.js`: build the list without the copies whose main picture is in the list; add `, N smaller copies hidden` to the count line only when there are copies; replace the Delete, Rename and Replace boxes of a picture that has copies with one plain sentence.
3. Write `admin-files-copies.test.ts` (20 tests); relax the import guard in `hosting-srcset.test.ts` so `files-screen.js` may import `hosting-srcset.js`.
4. Make deliberate mistakes and see the tests fail.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes (all older tests unchanged).
- With copies in the list, the grid shows only the main pictures and the count line says how many copies are hidden.
- Without copies, the screen looks and works exactly as before.
- A picture with copies shows a plain sentence instead of Delete, Rename and Replace; nothing is sent.
- A copy whose main picture is missing stays visible.
- `makeVariants` is still named in no dashboard file except `hosting-pipeline.js` and `hosting-copies.js`.
