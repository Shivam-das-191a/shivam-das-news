## Goal
The build stops when a `lang` or `xml:lang` is not a language code (such as `english` or `en_US`) or a `dir` is not `ltr`, `rtl` or `auto`; it warns on a tag whose `lang` and `xml:lang` name different languages.

## Why it matters
A screen reader chooses its voice from `lang`. A wrong value is ignored without a word, so the page or a quotation in it is read in the wrong voice. A `dir` that is not real is ignored by the browser. A post written by the owner by hand (PLAN 37) can carry a quotation with `lang="french"` instead of `lang="fr"`.

## Steps
1. New `site/scripts/lang-check-lib.mjs` with `checkLang(html)` and `isValidLang(value)`.
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `lang-check.test.ts` (31 cases, with a fake dist folder run of the real gate and a read of the real base layout).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with a bad value added.
5. Version 0.101.128, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- `lang="english"`, `lang="en_US"` and `dir="left"` fail the gate.
- A tag with `lang="en"` and `xml:lang="fr"` only warns.
