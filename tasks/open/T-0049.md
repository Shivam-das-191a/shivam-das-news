## Goal
`site/public/admin/js/hosting-setup.js` has `hostingSetup({ cfg, gh, postPath, serializePost, existing?, fetch?, optimizeDeps? })`: it makes the `deps` that `hostingFlow` needs from `admin/config.json` (optional key `imagesUrl`) and the signed-in GitHub client, or says in one plain sentence why it cannot. It does not fetch, write or throw.

## Why it matters
The flow (3c-7) needs many parts (the Worker call with the token, the picture step, the own website names, the media file path). If the hook into Save had to build them, one mistake there could send the token to a wrong address or turn the feature on by accident. An empty `imagesUrl` keeps it OFF. Nothing calls it yet, so the live site and the dashboard do not change.

## Steps
1. Read `hosting-flow.js`, `hosting-pipeline.js`, `hosting-client.js`, `hosting-optimize.js`.
2. Write `hosting-setup.js`.
3. Write `site/tests/unit/hosting-setup.test.ts` (including two tests with the real `savePostWithHosting` in preview mode).
4. Make deliberate mistakes and see the tests fail; close the gaps.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` and `npm run tasks:check` pass; older tests pass unchanged.
- An empty or missing `imagesUrl` gives `off: true`; a bad address or client gives one plain sentence with no token and no address.
- The token goes only into the Bearer header of the call to `<imagesUrl>/fetch`.
- No other file imports it yet; the file has no network, storage, page access or emoji.
