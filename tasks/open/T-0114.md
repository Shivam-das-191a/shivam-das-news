## Goal
The build stops when the style or a page makes something fixed and wider than a 320px phone screen, so a page cannot scroll sideways by mistake.

## Why it matters
POLISH (Accessibility and Mobile) asks for no horizontal scroll at 320px. Until now nothing checked it. Most readers are on phones; a page that scrolls sideways is hard to read and hurts the search ranking.

## Steps
1. New `site/scripts/side-scroll-lib.mjs` with `checkSideScrollCss(css, flags)` and `checkSideScrollHtml(html)`.
2. `site/scripts/validate-html.mjs`: run the style check once on all built style, and the page check on every built page.
3. `site/src/styles/global.css`: the `.brand` site name rule (`white-space: nowrap` with nothing to save a long name) is split: the name now gets `overflow: hidden` and `text-overflow: ellipsis`. Nothing changes for today's name.
4. New test `side-scroll.test.ts` (55 cases, with a fake dist folder run of the real gate and a read of the real style).
5. Run the gate on today's real build, then on throw away copies with the real build broken.
6. Version 0.101.116, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A rule or an inline style with a fixed width over 320px (and no cap) fails the gate; the same rule inside a `min-width` media query over 320px, or capped with `max-width: 100%`, passes.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card). `global.css`: one rule split in two.
- Check: `npm test`: 204 files and 4502 tests passed (before: 203 and 4447). `npm run build` ended with `Validation passed.` on today's real build with no new message (with `SITE_URL` set).
- Throw away copies of the real build in `/tmp` (not in the ZIP): `.x{width:640px}` added to the style of `dist/index.html`: exit code 1 and the line `dist: the rule ".x" sets width to 640px, wider than a 320px phone screen, so the page would scroll sideways; use max-width: 100% or put it in a min-width media query`. A `<div style="width:700px">` put in `dist/404.html`: exit code 1 and the line `dist/404.html: a <div> has an inline width of 700px, wider than a 320px phone screen; use max-width: 100%`.
- The first run of the new check on the real build gave one warning, for `.brand` (nowrap). It was fixed in `global.css` (step 3), not hidden.
- Not proved: a real phone or browser at 320px; the check reads the style text, it does not draw the page.
- Not verified live: no GitHub run of the validate workflow yet.

## If it goes wrong
Put back `validate-html.mjs` and `global.css` of v0.101.115, delete the library and its test.
