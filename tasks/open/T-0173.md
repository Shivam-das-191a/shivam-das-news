## Goal
The build warns when the text of a built page has two hyphens where a dash belongs (`left--then`, `2020--2021`, `left -- then`), and never stops the build for it.

## Why it matters
Text typed fast, pasted from Word or imported from Blogger often has two hyphens for a dash. A reader sees each one at once and trusts the site a little less. Nothing in the build read the dashes of the text.

## Steps
1. New `site/scripts/dash-check-lib.mjs` with `checkDoubleHyphen(html)` (reads the title and the body text of every page; an inline tag leaves no gap, a block tag, a `br` and a character reference end the run; comments and script, style, template, textarea, pre, code, kbd, samp, svg, noscript and select blocks skipped; attributes and the meta description not read; one message per page with a count; no errors).
2. The slip: exactly two hyphens with a letter or a digit on both sides, or with a space on both sides between two words.
3. Left out: three or more hyphens, a command option in a sentence (`run --help`), a pair at the start or end of a paragraph, a single hyphen, an en or em dash, code.
4. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
5. New test `dash-check.test.ts` (60 cases, with a fake dist folder run of the real gate).
6. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with slips added.
7. Version 0.101.175, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A page with `left--then` and `left -- then` gives one warning that names the page and counts 2 places; the build still passes.
- Clean dashes, `---`, `run --help`, a pair at the start of a paragraph, text in `pre` or `code` pass with no message.
