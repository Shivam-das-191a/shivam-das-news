## Goal
A new file `site/config/images.json` with `"hardBlock": false`. When the owner sets it to `true`, an outside picture in the text of a published or scheduled post is an ERROR in `npm run check:content` instead of a warning. It ships off, so nothing changes today.

## Why it matters
Decision 16 asks for a warning (proposed) or a hard block. The warning is built (v0.101.68); this adds the switch so the stricter choice is one word away, with no new code later.

## Steps
1. `config/images.json` with `{ "hardBlock": false }` (only the key that is used; no invented settings).
2. `validate-content-lib.mjs`: `checkPost` option `hardBlock` (only the value true makes it an error) and `checkImagesConfig` (the file must be an object; `hardBlock` must be true or false).
3. `validate-content.mjs`: reads `config/images.json`, reports a bad file, passes `hardBlock` on.
4. Tests (5 new cases, one runs the script with false, true and a text value), then five deliberate mistakes.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `hardBlock` false or missing: the same WARN as before and `CONTENT PASS`. With `true`: the same text as an ERROR and `CONTENT FAIL`. With `"true"` (text): a config error, and the post is still only a warning.
- A draft is never blocked. The shipped file has `hardBlock` false.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 164 files and 3420 tests passed, build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (66 cards).
- Deliberate mistakes: five made, four caught; the fifth gives the same result (the library also checks for the value true), so it cannot show.
- Not verified live: no GitHub run of the validate workflow yet.

## If it goes wrong
Set `"hardBlock": false` (or delete the file: a missing file means a warning only). To remove the code, put back the files of v0.101.68.
