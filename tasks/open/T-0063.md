## Goal
A picture that has smaller copies (`variants` in `config/media.json`) is written on the public page with `srcset` and `sizes`, so a phone loads the 480 or 800 pixel copy and not the big file. A picture with no copy is written as before.

## Why it matters
This is the part that makes copies useful: readers on phones get smaller files and the site gets faster. Until now copies, if switched on, were made but no page used them.

## Steps
1. Read `hosting-srcset.js` (the dashboard rule), `media-alt.ts`, `picture.ts`, the three places that write a picture (`PostCard.astro`, `index.astro`, the article page) and `global.css` (the widths for `sizes`).
2. New `site/src/lib/picture-set.ts`: `pictureSet(map, src, sizes, exists?)`, `copyPath`, `COPY_WIDTHS`, `SIZES` (article, lead, card). Pure.
3. `picture.ts`: `setOf(src, sizes)` binds it to `config/media.json` and checks that each copy file is in `public/`.
4. The three templates add `srcset` and `sizes` from `setOf`. `src`, `width`, `height`, `loading` and `fetchpriority` stay as they were.
5. Tests (`picture-set.test.ts`), then a real build with a temporary picture and three copies to read the `img` tags.
6. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A picture with `variants` and a stored `width` gets `srcset` (copies narrowest first, then the main file with its true width) and `sizes`; one without gets neither, and its `img` tag is exactly as before.
- A copy whose file is missing is not named. A copy name, a query or hash, a non-webp and an outside address get no srcset.
- Nothing is switched on: the shipped `config/media.json` is empty, so the live site does not change.

## If it goes wrong
Remove `srcset={...}` and `sizes={...}` from the three templates (or put back the files of v0.101.65). The old `img` tags work with no other change.
