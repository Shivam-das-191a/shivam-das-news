## Goal
`site/public/admin/js/hosting-run.js` has `hostPost(post, deps)`: for one post it plans (T-0040), asks the images Worker for the pictures in groups of 30, finds a picture already hosted by address or by hash, optimizes, makes the SEO name and path, writes the `config/media.json` row, and rewrites the post. It returns the new post, the new files, the new map and one line for each picture; it writes nothing.

## Why it matters
This is the heart of Part 3: the engine that the Save, the Paste preview and the XML import will share. Everything that touches the world (the Worker, the browser image step, the hash, the clock) is passed in, so it is tested with fakes, including the real Worker code behind a fake network. Nothing calls it yet, so the live site and the dashboard do not change.

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- A good post is hosted: SEO names, `/media/YYYY/MM/` from the post date, the media row (source, hash of the downloaded file, size of the hosted file, UTC time, `autoAlt` only when made), the post rewritten, no outside picture left.
- A failed, refused or agency picture stays in the post as it was and is listed (Retry list); a run with only failures changes nothing.
- The same address (also with different `#fragment`) is downloaded once; the same bytes under another address reuse the file, also inside one run; a taken name gets `-2`, `-3`.
- A service that throws, refuses or sends damaged data, an optimizer that fails, a JPEG instead of WebP and a GIF over 5 MB each fail only that picture with a plain sentence; more than 30 pictures go in groups of 30; no valid date stops the run before any download.
