## Goal
`npm run check:content` prints a plain warning when the pictures in `site/public/media/` use more than 900 MB, so the owner knows it is time to plan Cloudflare R2.

## Why it matters
BUGS U12: a repository should stay under about 1 GB. Nothing told the owner when the picture folder was getting close.

## Steps
1. `validate-content-lib.mjs`: add `MEDIA_WARN_MB` (900) and `mediaSizeWarning(totalBytes, limitMb)`.
2. `validate-content.mjs`: add up the size of every file in `public/media/` and print the warning when it is above the limit; skip it when only some files are named.
3. New test `media-size-warning.test.ts`.
4. Deliberate mistakes, one at a time.
5. Version 0.101.100, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A folder above 900 MB gives one `WARN  public/media: ...` line and the check still ends with `CONTENT PASS`; a folder at or below 900 MB gives no such line.

## Evidence
- Files changed: the paths of this card (new files: the test and this card).
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 189 files and 3997 passed (before: 188 files and 3984), build pass, content pass, tasks pass (97 cards). The budget warning is the old one (CHANGELOG, INCOMPLETE; decision 43).
- Deliberate mistakes: five made one at a time (limit 9000 instead of 900, `<` instead of `<=` at the limit, the skip when files are named removed, a warning made an error, the file sizes not read). Every one was caught at once. The files were put back after each and the tests passed again.
- Not verified live: no GitHub run of the validate workflow yet.

## If it goes wrong
Put back `validate-content-lib.mjs` and `validate-content.mjs` of v0.101.99 and delete the new test. The check then has no size warning, as before.
