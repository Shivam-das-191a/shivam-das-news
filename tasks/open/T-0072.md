## Goal
When `maxWidth` in `site/config/images.json` is above 0, a picture of our own site that is wider than that many pixels (the top picture, the share picture, or a picture inside the text of a published post) gives a WARNING in `npm run check:content`.

## Why it matters
Very wide pictures make pages slow on phones. The reader of v0.101.74 makes the check possible. It ships off (value 0), so nothing changes today.

## Steps
1. `validate-content-lib.mjs`: `tooWide`, `measure` (size and width together), `maxWidth` and `imageHead` in `checkPost`, and the `maxWidth` rule in `checkImagesConfig`.
2. `validate-content.mjs`: read `maxWidth`, and `imageHead` reads the first 256 KB of a picture file.
3. `config/images.json` gets `"maxWidth": 0`; the shipped-file test is updated; 8 new tests; six deliberate mistakes.
4. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `maxWidth` 0 or missing: the same result as v0.101.74. With a number: a WARN for each file that is wider, and still `CONTENT PASS`. A draft is never checked.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 166 files and 3465 tests passed, build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (72 cards).
- Deliberate mistakes: six made, six caught.

Set `"maxWidth": 0` in `site/config/images.json`. To remove the code, put back `validate-content-lib.mjs` and `validate-content.mjs` of v0.101.74 and delete `site/tests/unit/max-width.test.ts`.
