## Goal
The build stops when a `style="..."` attribute holds something a browser throws away: a declaration with no colon or no value, a property that is a typo of a real one, a number with no unit in a length, a unit or a keyword that is a typo, a hex color with the wrong number of digits, a bracket or quote never closed, a pasted rule, or two declarations joined with no semicolon; it warns on an empty style attribute, `expression(` and the same property twice with the same value.

## Why it matters
One `width:300` or `colour:red` in a post makes the browser drop the style with no message, so the page looks wrong and nobody knows why. The dashboard preview does not show it. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry these. Until now only the width inside a style attribute was read (`side-scroll-lib.mjs`).

## Steps
1. New `site/scripts/style-attr-lib.mjs` with `checkStyleAttrs(html)` (comments, script, style and template blocks skipped; custom and vendor properties and template expressions left alone).
2. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
3. New test `style-attr.test.ts` (96 cases, with a fake dist folder run of the real gate and a read of eight real templates).
4. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with bad markup added.
5. Version 0.101.155, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- `style="width:300"` fails the gate and names the page.
- An empty `style=""` only warns.
