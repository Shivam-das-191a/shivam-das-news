## Goal
The build stops when a `<style>` block of a page has a `{` never closed, a `}` with no opening one, a `{` with no selector, a comment or a quote never closed, or a rule with the faults of a style attribute (no colon, a property typo, a number with no unit, a bad hex color, two declarations joined with no semicolon); it warns on an empty `<style>` block and the same property twice with the same value.

## Why it matters
One missing `}` in a pasted `<style>` block makes the browser drop that rule and every rule after it, with no message, so the page looks wrong and nobody knows why. The dashboard preview does not show it. A post written by hand (PLAN 37) or an old Blogger post can carry these. Until now only the `style="..."` attributes were read (`style-attr-lib.mjs`).

## Steps
1. New `site/scripts/style-block-lib.mjs` with `checkStyleBlocks(html)` (comments, script and template blocks skipped; font-face, property and page rules, custom and vendor properties left alone).
2. `site/scripts/style-attr-lib.mjs`: move the declaration loop into the exported `checkDeclarations(parts, err, warn)`; nothing it reports changes.
3. `site/scripts/validate-html.mjs`: import the new check, run it on every built page, name it in the first comment line.
4. New test `style-block.test.ts` (76 cases, with a fake dist folder run of the real gate and a read of the real style sheet).
5. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with bad markup added.
6. Version 0.101.156, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A `<style>` block with a `{` never closed fails the gate and names the page and the rule.
- An empty `<style></style>` only warns.
