## Goal
The build stops when the style draws a button, a link, a menu summary or a field smaller than 24px wide or tall, and it warns (does not stop) when one is drawn under 44px.

## Why it matters
POLISH (Mobile) asks for tap targets of at least 44px. A reader with a thumb, or with a hand that shakes, misses a 20px button and hits the one next to it. WCAG 2.2 (2.5.8) sets 24px as the least that is allowed; this site's own rule is 44px.

## Steps
1. New `tap-targets-lib.mjs` with `controlClassesOf(html)` (the class names that sit on a control of a built page) and `checkTapTargets(css, classes)`.
2. `validate-html.mjs`: collect the control classes of every built page, then check the style once with them.
3. New test `tap-targets.test.ts`.
4. Run the check on today's real build first, then on the real build with one size made too small, then run deliberate mistakes in the library, one at a time.
5. Version 0.101.110, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A control drawn under 24px fails the gate; a control between 24px and 43px only warns; 44px and more passes with no message.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card).
- Check: `npm test`: 199 files and 4288 tests passed (before: 198 and 4216). `npm run build` ended with `Validation passed.` on today's real build.
- Real build today: one new warning, `".dot" is drawn 38px wide and 38px tall` (the colour style buttons in the menu drawer, `site/src/styles/global.css`). No error. Every other control is 44px or more; the checkbox and radio boxes (22px) are left to their 44px labels by rule.
- Real build with one size made too small (a throw away copy of `dist` in `/tmp`, not in the ZIP): `.dot` made 20px by 20px in `dist/index.html`: `Validation failed` and exit code 1, with the line `".dot" is drawn 20px wide and 20px tall; a tap target must be at least 24px each way (WCAG 2.5.8)`.
- Deliberate mistakes: fifty-one made one at a time in the library. Forty-six were caught at once; five were NOT (the `@keyframes` skip, the `~` combinator with no spaces, a brace inside a string, a brace inside a url, and spaces inside an attribute selector); test lines were added and all fifty-one are now caught. One real fault was found by the first test run and fixed: a quoted `[type="checkbox"]` was read as an empty type.
- Not verified live: no GitHub run of the validate workflow yet.

## If it goes wrong
Put back `validate-html.mjs` of v0.101.109 and delete the library and the test.
