## Goal
The build stops when the alt text of a picture is only a file name or a camera or screenshot name (`IMG_2041.jpg`, `DSC00123`); it warns on an alt that is one empty word (`image`, `photo`), one that starts with `image of`, one over 125 characters and one of blanks or marks only.

## Why it matters
A screen reader reads the alt aloud and a search engine reads it as the description of the picture. `img-check-lib.mjs` only asks whether an alt attribute is there, so a file name pasted by a phone or an importer passed with no message. Nothing read what the alt says.

## Steps
1. New `site/scripts/alt-text-lib.mjs` with `checkAltText(html)` (an empty alt is left alone; comments and script, style and template blocks skipped; common entities turned into letters).
2. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
3. New test `alt-text.test.ts` (38 cases, with a fake dist folder run of the real gate).
4. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with bad alt text added.
5. Version 0.101.162, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A picture with `alt="IMG_2041.jpg"` fails the gate and names the page; `alt="image"` is a warning only.
- An empty `alt=""` and `alt="Shivam Das News logo"` pass with no message.
