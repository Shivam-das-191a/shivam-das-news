## Goal
When `site/config/images.json` has websites in `blockHosts`, the Save of the editor does not host pictures from those websites (or their sub names): they are refused. With an empty, missing, wrong or broken list nothing changes.

## Why it matters
The build check already stops a live post with a picture from a blocked website (Part 7b), but the Save of the editor did not know the list, so it could still copy such a picture into the repository. Now the owner can block a website with no code change and no new secret. The shipped list is empty, so today nothing changes.

## Steps
1. `images-setting.js`: add `customBlockHosts` (the valid website names, or `undefined`); `hostingSettingsFromText` adds `blockHosts` to its answer only when there is a valid name.
2. `hosting-hook.js`: take `blockHosts` from the same one read (a list of the caller wins) and give it to `startHostingSave`.
3. `hosting-save.js`: give `blockHosts` to `hostingSetup`.
4. `hosting-setup.js`: add the websites to the block list (the dashboard list, or an empty list), never remove one, no repeat.
5. `images-screen.js`: the row "Websites never allowed" gets a new `use` word `buildSave`.
6. Tests: new `hosting-block-hosts-save.test.ts` (38 cases); `images-screen.test.ts` changed to the new truth.
7. Twelve deliberate mistakes.
8. Version, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With a website in `blockHosts` the Save makes no fetch and no picture commit for that website (and its sub names); with every other text the Save works as before.
- No token or address is shown in any message.
