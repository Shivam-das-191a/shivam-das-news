## Goal
The build stops when a `max`, `min`, `step` or `value` of a progress bar, a meter or a number or range field is not a number; it warns when a value is outside its own range, a `min` is above its `max` or a `step` is 0 or below.

## Why it matters
The browser quietly repairs or ignores these typos, so the bar, the gauge or the field behaves differently from what the writer meant, and the dashboard preview shows nothing wrong. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry them.

## Steps
1. New `site/scripts/range-check-lib.mjs` with `checkRanges(html)` (one pass over the progress, meter and input tags; only an input of type number or range is read; comments, script, style and template skipped).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `range-check.test.ts` (64 cases, with a fake dist folder run of the real gate and a read of the base layout and the post card).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.145, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A `<progress max="abc">` fails the gate and names the page.
- A `<progress max="10" value="11">` only warns.
