## Goal
Renaming a picture from the Files screen also renames its smaller copies (`name.480w.webp`, ...), adds a 301 for each copy and moves the notes, all in the same ONE commit. A picture with copies can be renamed again (the lock of 4c-4a is lifted for rename only).

## Why it matters
A copy left under the old name would be a file that no page can reach and that the Files screen hides, and a later `srcset` would point at nothing. This part makes rename safe before copies are switched on. Replace stays locked for a picture with copies (4c-4d).

## Steps
1. Read `file-rename.js` (`planFileRename`), `hosting-srcset.js` (`variantsOnList`, `variantPath`, `parseVariant`), `app.js` `onRename` and `files-screen.js` `renameBox`.
2. `file-rename.js`: `planFileRename` finds the copies that exist in `taken`, builds the new copy names with `variantPath(newPath, width)`, refuses a name when a copy of the new name already exists, moves each copy (`moves`: the picture first), adds a 301 for each copy with the same loop and chain rules, updates posts that name a copy, and moves the media entry (with its `variants` note). It also returns `copies` and `counts.copies`.
3. `app.js` `onRename`: read the bytes of each copy and put each move in the commit; the message ends with `and N smaller copies`.
4. `files-screen.js`: the Rename box is no longer locked; the question and the answer name the copies; the screen's own list of paths follows the new names (so a later Delete still takes the copies along).
5. Tests: new cases in `file-rename.test.ts` and `admin-files-copies.test.ts`, one full dashboard case in `admin-file-rename.test.ts`; the import guard in `hosting-srcset.test.ts` allows `file-rename.js`.
6. Make deliberate mistakes and see the tests fail.
7. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A rename of a picture with two copies makes ONE commit: the picture and both copies moved, the changed posts, `config/redirects.json` with three 301s, and `config/media.json` with the entry under the new name; the message says "and 2 smaller copies".
- A rename of a picture without copies is exactly as before.
- A copy of another picture is never moved. A copy is moved only when it is in the list of files that exist now.
- A rename is refused when a copy of the new name already exists, and when the redirects would pass the Cloudflare limit.
- Replace of a picture with copies still shows the plain sentence.
- `makeVariants` is named in no dashboard file that switches copies on.
