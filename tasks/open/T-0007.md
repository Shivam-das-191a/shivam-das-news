## Goal
Every pull request and every push to `main` runs the content check, the tests and the build, and a bad post is refused before it can break the site.

## Why it matters
Today a broken post stops the build and nothing new can be published until someone fixes it. This check makes direct AI and dashboard commits safe, and it is the base of Connected apps (PLAN 38).

## Steps
1. Read `CODING_PLAN.md` Phase 3d Parts 2 to 4 and `LOGICS.md` Section 26.1.
2. Write `scripts/validate-content.mjs` with the shared rules and tests.
3. Add `.github/workflows/validate.yml` (runs install, tests, content check, build).
4. Add the task check (`npm run tasks:check`) when it exists.
5. Bump the version and write the changelog (`VERSIONING.md`).

## Done when
- A pull request with a post that has no `imageAlt` fails the check with a plain message.
- A correct pull request passes.
- `npm test` and `npm run build` pass.

## Evidence
(Pull request links for one failing and one passing example, the Actions run links, the test summary.)

## If it goes wrong
Remove `validate.yml`; the site works as before.

## Stop and ask the owner if
- The workflow needs a secret or a permission change in GitHub settings.
- Required status checks on `main` are to be switched on (that is the owner's setting).
