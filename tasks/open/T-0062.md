## Goal
`hosting-setup.js` gives the picture hosting the function that makes the smaller copies (`makeVariants`), but ONLY when `site/public/admin/config.json` has `"imageCopies": true`. The file ships with `"imageCopies": false`, so nothing changes until the owner turns it on.

## Why it matters
Delete (4c-4b), Rename (4c-4c) and Replace (4c-4d) are now safe for a picture with copies, so the last thing that kept copies off can be a switch the owner can see and flip. The page does not use the copies yet (`srcset` is part 4c-5), so a reader sees no change either way.

## Steps
1. Read `hosting-setup.js`, `hosting-pipeline.js` (the optional dep `makeVariants`), `hosting-copies.js` and `hosting-optimize.js` (`makeVariantMaker`).
2. `hosting-setup.js`: new `copiesEnabled(cfg)` (true only for the value true); `hostingSetup` adds `deps.makeVariants = makeVariantMaker(copyDeps)` only when it is true. Nothing else in the deps changes. A missing `imagesUrl` still means the whole feature is off.
3. `site/public/admin/config.json`: add `"imageCopies": false`.
4. Tests: 11 new cases in `hosting-setup.test.ts` (off by default, only true switches it on, needs `imagesUrl`, the same deps plus `makeVariants`, joined to the real pipeline with the switch off and on, 480 pixels or less, a preview never makes copies, the config file, the source). Three guards that said "copies stay off because no dashboard file names makeVariants" now say "only `hosting-setup.js` names it, behind the switch".
5. Make deliberate mistakes and see the tests fail.
6. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `imageCopies` missing, false, `"true"` (text), 1 or anything else than the value true, no copy is made and the deps have no `makeVariants`.
- With `imageCopies: true` and a valid `imagesUrl`, a hosted 1600 pixel wide picture is saved with its 480, 800 and 1200 pixel copies in the same ONE commit. A picture of 480 pixels or less gets none. A preview makes none.
- `makeVariants` is named in no other dashboard file than `hosting-setup.js`.
- The shipped `config.json` has `"imageCopies": false`.

## Evidence
- Tests: see the changelog entry of 0.101.65.
- Deliberate mistakes: five made, five caught.
- Not verified live: tested with fakes and jsdom only; no real browser (the canvas that draws the copies is faked), Worker or GitHub token.

## If it goes wrong
Set `"imageCopies": false` (or delete the line) in `site/public/admin/config.json`: copies are off again at once. To remove the code, put back the old `hosting-setup.js`, the old `config.json` and the old guards (git history of v0.101.64) and revert the version.

## Stop and ask the owner if
- The cases in `AI_START_HERE.md` Section 4.
- The owner wants copies on before `imagesUrl` is set: it cannot work, the Worker must be deployed first.
