## Goal
No page has a heading before its `h1`, and no listing page skips a level, so the build prints no heading warning (today: 17).

## Why it matters
The heading check of v0.101.109 warned on every page: the two titles of the menu drawer ("Categories", "Colour style") were `h3` and came first in the page, before the `h1`. Once a real post is published, the category, tag and author pages would also warn, because the post card is an `h3` directly under the `h1`. A screen reader user and a search engine read the heading list as the outline of the page.

## Steps
1. `Header.astro`: the two drawer titles become `<p class="menu-h">`; the colour buttons get `role="group"` and `aria-labelledby` to their title.
2. `global.css`: `.menu h3` becomes `.menu .menu-h` with the same look; `.post h3` becomes `.post h3,.post h2`.
3. `PostCard.astro`: new prop `level` (default 3); the title is an `h2` when it is 2.
4. `Listing.astro` (category, tag, author pages) passes `level={2}`. Home, 404 and Related keep the default, because they have an `h2` section above the cards.
5. New test `heading-templates.test.ts` (7 cases). Run `npm test` and `npm run build`; then a throw away copy of the site with one published post, to see the listing page.
6. Version 0.101.113, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` with no heading warning.
- On a build with one published post, the category page has the headings `h1, h2` and no warning.
- The drawer titles look the same as before (same size, case, spacing, colour).
