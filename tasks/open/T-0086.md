## Goal
Plain functions can turn the values of a picture settings form into a checked settings object and into the new text of `config/images.json`, and can say what would change (`imagesFromForm`, `imagesFileText`, `imagesChanges`, `imagesFormValues`). Nothing calls them yet.

## Why it matters
The form that changes the settings needs strict checks and a safe file text before it can exist. This part builds and tests only that logic, so the later page and the save (which waits for decision 24, the write mode) have nothing left to get wrong.

## Steps
1. `images-form.js`: add the four functions. No page, no fetch, no save, no GitHub, no storage. A wrong value is an error with a plain sentence and is never repaired; a key missing from the form keeps its current value.
2. `images-form.test.ts` (64 tests): the form values and the round trip, good input, every kind of wrong input, the same answers as `checkImagesConfig` of the build script (numbers, lists, names, naming order), the file text (keys, order, unknown keys kept, bad current file), the change list, and the file itself (no page, no write, no emoji, not called yet).
3. Eight deliberate mistakes.
4. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- For many values, the form accepts exactly what `checkImagesConfig` accepts, and every file text it makes passes `checkImagesConfig`.
- The shipped settings give back the shipped `config/images.json` (same keys, same values, same order).
