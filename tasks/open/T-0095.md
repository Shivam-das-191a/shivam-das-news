## Goal
A new function `saveImagesSettings` checks what the picture settings form holds and writes `site/config/images.json` to GitHub in one commit, the same way the dashboard already saves its other settings. Nothing calls it yet: no button, no screen change.

## Why it matters
The form of Part 7v shows the eleven settings but cannot save, so the owner still has to edit `config/images.json` by hand. This part builds and proves the save on its own, so the next part only has to add the button.

## Steps
1. New `site/public/admin/js/images-save.js` with `saveImagesSettings(gh, cfg, raw, opts)`: read the file and its sha, optional check that the file is still the one the form was filled from (`opts.loadedText`), strict check with `imagesFromForm`, new text with `imagesFileText` (unknown keys kept), no commit when the file already says the same, one `gh.put` with the sha, plain fixed sentences for every failure, never throws.
2. New `site/tests/unit/images-save.test.ts` with a fake GitHub.
3. Deliberate mistakes, one at a time.
4. Version 0.101.98, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A good save makes exactly one `gh.put` to `site/config/images.json` with the sha just read; a wrong value, a changed file, a failed read or a failed write writes nothing and gives a plain sentence; values that say the same as the file write nothing.
- No other file calls the new function; the dashboard and the live site do not change.

## Evidence
- Files changed: the paths of this card (two new files: `site/public/admin/js/images-save.js`, `site/tests/unit/images-save.test.ts`; the rest are the version and document files).
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 188 files and 3966 passed (before: 187 files and 3920), build pass, content pass, tasks pass (95 cards). The budget warning is the old one (CHANGELOG, INCOMPLETE; decision 43).
- Deliberate mistakes: nineteen made one at a time (sha not given, validation skipped, always write, 409 and 422 not a conflict, 403 not a permission error, both file-changed checks removed, a missing file treated as an error, any read error ignored, GitHub text leaked from a read error and from a write error, the file ignored as the base, wrong commit message, wrong path, no-client check removed, unknown keys dropped, changed always true, new sha dropped). Every one was caught at once. One more change that could not alter any answer (so it is no mistake) was left out. The file was put back after each and the tests passed again.
- Not verified live: no GitHub run of the validate workflow yet; the function has not been tried with the real GitHub (nothing calls it).

## If it goes wrong
Delete `site/public/admin/js/images-save.js` and `site/tests/unit/images-save.test.ts`. Nothing else uses them.
