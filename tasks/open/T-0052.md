## Goal
`save()` of the post editor in `site/public/admin/js/app.js` calls `runHostingSave` after the checks and before the normal write, so pictures on other websites are hosted in ONE commit with the post; with `imagesUrl` empty (today) Save works exactly as before.

## Why it matters
This is the last hand edit of Phase 3c Part 3c-8: after it, the owner only has to deploy the images Worker and put its address in `admin/config.json` to switch the feature on.

## Steps
1. Read `save()` and `editorView` in `app.js` and `hosting-hook.js`.
2. Add the import, make `orig` a `let`, add the `hostBox` list place, and the few lines in `save()`.
3. Write `site/tests/unit/admin-app-hosting.test.ts` (jsdom; the real app behind a fake GitHub and a fake picture service).
4. Make deliberate mistakes in `app.js` and see the tests fail; close the gaps.
5. Change the old test line that said `app.js` must not import `hosting-hook`.
6. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes (all older tests unchanged, except the one import line named in step 5).
- With `imagesUrl` empty, or with no outside picture, Save makes no Worker call and one normal write, as before.
- One hosted picture gives ONE commit that holds the post file, no second write of the post, and the editor shows the new address.
- A failed commit stops Save, writes nothing and shows no token. When every picture fails the post is saved as it was and the list stays for Retry. Retry after that makes one commit, updates the editor and the list goes.
