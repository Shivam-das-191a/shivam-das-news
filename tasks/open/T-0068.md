## Goal
`site/config/images.json` gets `sizeWarnKb` (shipped 0, off). With a number above 0, a front matter picture file of a published post that is bigger than that many KB is a WARNING in `npm run check:content`.

## Why it matters
PLAN 34.10 lists a maximum size. A big picture slows the page on a phone. The owner can switch on a limit and the check tells which file is too big before it goes live. It ships off, so nothing changes today.

## Steps
1. `config/images.json`: add `"sizeWarnKb": 0`.
2. `validate-content-lib.mjs`: `checkPost` options `sizeWarnKb` and `imageBytes`, the `tooBig` warning for `image` and `ogImage`, and `checkImagesConfig` for the new key.
3. `validate-content.mjs`: read the number and measure the files in `public/`.
4. Tests (6 new cases, one runs the script with 0, 2, 5 and a text value), then five deliberate mistakes.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `sizeWarnKb` 0 or missing: the same result as v0.101.70. With a number: a WARN for a published post whose `image` or `ogImage` file is bigger, and still `CONTENT PASS`. With a wrong value (for example `"300"`): an error in the config check and no size warning.
- A draft is never checked. The shipped file has `sizeWarnKb` 0.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 164 files and 3433 tests passed, build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (68 cards).

## If it goes wrong
