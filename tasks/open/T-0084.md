## Goal
A dashboard screen module can draw all eleven settings of `config/images.json` in plain words, read only (`imagesScreen`, `imagesRows`). Nothing calls it yet.

## Why it matters
Parts 7a to 7q added the settings and the careful reader, but the owner cannot see the values anywhere in the dashboard. A read only screen comes first, so the owner can look before any form can change a file.

## Steps
1. `images-screen.js`: add `imagesRows` (eleven rows through `imagesSettingsOf`), `imagesScreen` (`{ el, update }`), `NAME_WORDS`, `USE_WORDS`. Every text is a text node; no button, no input, no fetch, no storage.
2. `images-screen.test.ts` (26 tests): the rows and their order equal the shipped file, plain words for the shipped and for other values, website lists (none, three, more than ten), the naming order, bad input, the "use" line of each row checked against the real code, the screen is read only, no HTML is built, nothing else calls the file.
3. Six deliberate mistakes.
4. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- The screen shows eleven rows, one for every key of `site/config/images.json`, and has no button, input or link.
- A website name that is not a clean name never reaches the page as HTML.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 177 files and 3574 passed (before: 176 files and 3548), build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (84 cards). The budget warning is the old one (CHANGELOG, INCOMPLETE; decision 43).
