## Goal
`site/config/images.json` gets a `blockHosts` list (shipped empty). A picture in the text of a published or scheduled post from a listed website is an ERROR in `npm run check:content`, with or without `hardBlock`.

## Why it matters
PLAN 34.10 lists a block list of hosts. The owner can name a website whose pictures must never go live (for example one with a bad licence record), and the check stops it before it is published. It ships empty, so nothing changes today.

## Steps
1. `config/images.json`: add `"blockHosts": []`.
2. `validate-content-lib.mjs`: `HOST_NAME`, `hostBlocked`, `checkPost` option `blockHosts`, and `checkImagesConfig` for the new key.
3. `validate-content.mjs`: read the list and pass it on.
4. Tests (7 new cases, one runs the script with an empty list, a listed host and a bad entry), then five deliberate mistakes.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `blockHosts` empty or missing: the same result as v0.101.69. With a listed website: an ERROR for a live post that shows its picture, `CONTENT FAIL`. With a bad entry (for example `"https://x.com"`): an error that names the entry number.
- A draft is never blocked. The shipped file has an empty list.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 164 files and 3427 tests passed, build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (67 cards).
