## Goal
The build stops on a stray `</br>`; it warns on two or more `<br>` in a row, a paragraph that holds only a `<br>`, a `<br>` at the start or end of a paragraph, next to a block tag or directly inside a list or table, and on an end tag of an empty element such as `</img>`.

## Why it matters
An imported Blogger post and a pasted block often hold `<br><br>` in place of a new paragraph. The page then has no real paragraphs for a screen reader or for Google, the spacing cannot be set in CSS, and a `<br>` inside a list or table is moved by the browser. A stray `</br>` is read by every browser as one more line break. Nothing in the build read the line breaks.

## Steps
1. New `site/scripts/break-check-lib.mjs` with `checkBreaks(html)` (comments and script, style, template, textarea, pre and svg blocks skipped; one message per kind with a count).
2. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
3. New test `break-check.test.ts` (40 cases, with a fake dist folder run of the real gate).
4. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with bad breaks added.
5. Version 0.101.165, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A page with `<p>a</br>b</p>` fails the gate and names the page; `<p>c<br><br>d</p>` is a warning only.
- One `<br>` between two pieces of text, and any `<br>` in a `<pre>`, pass with no message.
