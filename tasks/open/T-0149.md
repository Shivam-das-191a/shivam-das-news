## Goal
The build stops when the `pattern` of an `<input>` is not a regular expression in any browser; it warns when a pattern is dropped only by new browsers, when `pattern`, `accept` or `multiple` sits on a field that does not read it, and when a `minlength` is above the `maxlength`.

## Why it matters
A broken `pattern` is dropped by the browser without a word, so the field accepts anything while the writer believes it is checked. New browsers read a pattern with the `v` flag, so `[\w-]+` works in an old browser and is dropped in a new one. `form-controls-lib.mjs` reads only the type and the number form of `maxlength` and `minlength`; nothing read these rules. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry them.

## Steps
1. New `site/scripts/input-rules-lib.mjs` with `checkInputRules(html)` (one pass over all tags; comments, script, style and template skipped; entities in the pattern are decoded first).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `input-rules.test.ts` (59 cases, with a fake dist folder run of the real gate and a read of the base layout, the contact form, the search page and the notifications page).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.151, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when

- An `<input pattern="(abc">` fails the gate and names the page.
- An `<input type="text" accept="image/*">` only warns.
