## Goal
When the owner sets the repository variable AUTO_MERGE to on, a green, content-only pull request from an ai/T-0000 or human/T-0000 branch is merged by itself; with the variable off, nothing is ever merged.

## Why it matters
Posts and pictures made by an AI go live without the owner clicking Merge, while code, settings, Workers and deletions always stay with a person.

## Steps
1. Write the rules in `site/scripts/automerge-lib.mjs` (reuse the risk rule of the task cards) and the reader of the pull request from the GitHub API.
2. Write `site/scripts/automerge.mjs` (prints AUTOMERGE OK or one SKIP line per reason).
3. Write `.github/workflows/automerge.yml`: starts after Validate, runs from main, never runs pull request code, merges only the checked commit.
4. Write the tests (rules, fake GitHub, script, workflow text) and make deliberate mistakes to prove they fail.
5. Write the owner steps and the warning about protecting main in `site/README.md`; bump the version, write the changelog, update the documents.

## Done when
- `npm test`, `npm run build`, `npm run check:content`, `npm run tasks:check` and `npm run preflight` pass.
- A draft, a fork, a wrong branch name, a code file, a deletion, a rename, a blocked label, a changed head commit and AUTO_MERGE off each give an `AUTOMERGE SKIP` line.
- After merge to main and with AUTO_MERGE on, one small content pull request merges by itself and one with a code file does not (owner or second key).

## If it goes wrong
Delete the repository variable AUTO_MERGE (the workflow then does nothing), or delete `.github/workflows/automerge.yml`. A merged pull request is undone with Revert in GitHub.

## Stop and ask the owner if
- The workflow needs a secret or a changed permission in GitHub settings.
- Branch protection or required checks on main are to be switched on (the owner's setting; the dashboard saves straight to main).
