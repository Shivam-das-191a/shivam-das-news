## Goal
`POST /fetch` of the images Worker works as PLAN 34.8 says: only a signed-in dashboard user (or the Action with a secret header) may call it; it takes at most 30 addresses and answers each with the picture as base64 bytes or a reason word; it stores nothing.

## Why it matters
Part 2a made the download rules; this part puts a door in front of them. The Worker is written and tested but NOT deployed and nothing calls it, so the live site is unchanged. The owner decides when to deploy.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 34.8, `workers/contact/index.js` (the sign-in and the answer style), `workers/shared/guard.js`, `workers/images/lib.js`.
2. Add to `lib.js` the total size limit of one call (`call_too_big`) and `toBase64`.
3. Write `workers/images/index.js` (kill switch, path and method, caller check, request checks, rate limit, answer) and `workers/images/wrangler.toml` (no secret, a clear "not deployed" note).
4. Write `site/tests/unit/images-worker.test.ts` with a fake GitHub, a fake DNS and fake sites.
5. Make deliberate mistakes and see the tests fail; restore the code.
6. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- No token, another website, a user not on the list, a wrong secret, a body that is not JSON, a body that is too long, a wrong field, an empty or too long list, and a fast loop of calls are each refused with the right status.
- A good call returns the bytes as base64 with kind, size and final address; a failed picture gives a reason word and no data.
- `wrangler.toml` holds no secret and says that the Worker is not deployed.
