## Goal
A static page and a tag page can have their own search title and description, stored and checked, and their page heads use them when set.

## Why it matters
Pages and tags had no stored search fields, so the owner could not set how they look in Google. This is the data part; the screens come later.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 33.2 and the code of Part 6a.
2. Add `metaTitle` and `metaDescription` to the pages schema and use `listingHead` in the page route.
3. Add `config/tags.json` (shipped as `{}`), `src/lib/tags.ts`, and pass the fields in the tag route.
4. Add the page limits to `checkPage` and a new `checkTags`, and call it from the content check script.
5. Write the tests, make deliberate mistakes, build once with temporary values and restore them.
6. Bump the version, write the changelog, update `CODING_PLAN.md` and `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- With no search fields a page and a tag page head are exactly as before; with them the head uses the typed text.
