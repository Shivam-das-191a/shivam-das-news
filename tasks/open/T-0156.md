## Goal
The build stops when a page has no `<!doctype html>`, has a mistyped one, has it after other content, or names something other than `html`; it warns on an old identifier, a second doctype and a comment before it.

## Why it matters
A page with no valid doctype is drawn in quirks mode: old box sizes, odd line heights and table fonts. The reader sees a page that looks slightly wrong and no message reaches the owner. A page pasted by hand (PLAN 37) or an old Blogger page can lack the first line. Until now nothing read the first line of a page.

## Steps
1. New `site/scripts/doctype-check-lib.mjs` with `checkDoctype(html)` (blanks, a byte order mark and comments at the start are skipped; case is not read).
2. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
3. New test `doctype-check.test.ts` (35 cases, with a fake dist folder run of the real gate).
4. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with the doctype taken off.
5. Version 0.101.158, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A page with the doctype removed fails the gate and names the page.
- A page with `<!doctype html>` passes with no message.

## Evidence
