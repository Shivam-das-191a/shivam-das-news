## Goal
The build stops when a robots meta tag has a word that is a typo of a real one (`noindx`), a wrong value for `max-image-preview`, `max-snippet` or `max-video-preview`, `follow` with `nofollow`, or a meta name that is a typo of `robots`; it warns on an empty content, an unknown word, a list with spaces and no commas, and an old word such as `noodp`.

## Why it matters
`<meta name="robots" content="noindx">` looks right, but a crawler does not know the word and reads nothing: the page is indexed although the writer wanted it kept out. `<meta name="robot">` is not read at all. `head-check-lib.mjs` reads only "more than one robots tag" and "index and noindex together", so a typo of a word passed. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry these.

## Steps
1. New `site/scripts/robots-check-lib.mjs` with `checkRobots(html)` (one pass over all meta tags; comments, script, style and template skipped; a content written as a template expression is not read).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `robots-check.test.ts` (62 cases, with a fake dist folder run of the real gate and a read of the base layout, the search page and the 404 page).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.152, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A robots tag with `noindx` fails the gate and names the page.
- A robots tag with `noindex nofollow` (no comma) only warns.
