## Goal
The post editor has a Form tab and a File tab. The File tab shows the whole Markdown file (front matter and body). Writers and editors see it read-only; an admin can edit it and save it.

## Why it matters
PLAN 33.4 asks for a "File" tab with the raw Markdown and front matter, read-only for writers and editable for admins, with every save going through the validators. Part 8 (rename, replace, delete, bulk alt text) is complete, so this is the last open part of Phase 3b.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 33.4 and 33.5, `BUGS.md` group S, `public/admin/js/frontmatter.js`, `validate.js`, `roles.js`, and `editorView` and `save` in `app.js`.
2. Add `site/public/admin/js/file-tab.js` (`rawText`, `parseRaw`, `rawGuard`, `rawUnchanged`) and the role `post:raw` for admins only.
3. Add the Form and File tabs to `editorView`; add `saveRaw` (parse, role check, form-changes check, `validatePost`, one commit on the same file with the old sha).
4. Write the tests (the rules, the screen with the real `app.js` and a fake GitHub), make deliberate mistakes, run the whole suite and the build.
5. Bump the version, write the changelog, update `CODING_PLAN.md` and `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- A writer and an editor see the file but cannot type in it or save it; an admin can.
- A file with no front matter, a new handle, category or date on a live post, or any form-check error sends nothing.
- A good change is exactly one commit on the same file, with the old sha.
