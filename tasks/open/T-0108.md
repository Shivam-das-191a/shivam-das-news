## Goal
The build stops when a text colour of the built style is too weak on its background: the colour tokens must keep 4.5:1 in every look (light, dark, and each colour style), and a rule that sets both a text colour and a solid background is an error under 3:1 and a warning under 4.5:1.

## Why it matters
POLISH (Accessibility) asks for contrast of at least 4.5:1. Until now only `tests/unit/contrast.test.ts` read the colour tokens of `global.css` in the source; the build did not look at the style that is really shipped. A weak colour added in a new rule, or in a style block of a page, passed every check.

## Steps
1. New `contrast-lib.mjs` with `parseColor`, `contrastRatio` and `checkContrast(css)`.
2. `validate-html.mjs`: run `checkContrast` on the whole built style, with the font, print and tap target checks (messages start with `dist:`).
3. New test `contrast-check.test.ts`.
4. Run the check on today's real build first, then on a throw away copy of the real build with one colour made too weak, then put deliberate mistakes into the library one at a time.
5. Version 0.101.111, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A colour token under 4.5:1 in any look fails the gate; a rule with text and background under 3:1 fails it; between 3:1 and 4.5:1 only warns; 4.5:1 and more passes with no message.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card).
- Check: `npm test`: 200 files and 4365 tests passed (before: 199 and 4288). `npm run build` ended with `Validation passed.` on today's real build, with no new message (the only warnings are the 17 heading warnings of v0.101.109 and the `.dot` size warning of v0.101.110).
- Real build with one colour made too weak (a throw away copy of `dist` in `/tmp`, not in the ZIP): `--muted` changed from `#5a6b85` to `#b0b8c8` in one built page: `Validation failed` and exit code 1, with the lines `--muted on --bg is 1.99:1 in the looks light, light (grape), light (mint), light (sky), light (sunset); text must keep 4.5:1 (WCAG 1.4.3)` and the same for `--card`.
- Deliberate mistakes: thirty-two made one at a time in the library. Twenty-three were caught at once. Six were not and are explained here: four were real gaps in the tests (the 3:1 line, a rule on the root that has a text colour and a background, `:not([data-theme=dark])`, a url that holds a rule) and were closed with new test lines; one cannot happen (a ratio of exactly 4.5 is not reachable with a real colour pair); one was a change that has no effect (a fallback for a null that cannot be null at that point). Three could not be applied (the text was not in the file) and were left out. One real design fault was found while writing the test: a rule on the root with a text colour and a background was skipped as a token rule; it is now judged. The final run of the four closed gaps: all four caught.
- Not verified live: no GitHub run of the validate workflow yet.
