## Goal
When `site/config/images.json` holds its own valid `nameOrder`, the Save of the editor names NEW hosted pictures in that order. With the shipped order, no file, a broken file or a wrong order, the names are made exactly as before.

## Why it matters
The setting exists since Part 7a and the screen shows it, but nothing used it. Now the owner can choose which text names a picture (for example the caption before the alt text) with no code change and no new secret. The shipped value is the old behaviour, so today nothing changes.

## Steps
1. `images-setting.js`: add `customNameOrder` (a valid order that is not the shipped one, else `undefined`); `hostingSettingsFromText` adds `nameOrder` to its answer only in that case.
2. `hotlink.js`: `seoName` takes an optional fourth value `order`; the ways are tried in that order, a way not in the list is skipped, `handle` stays the last fallback.
3. `hosting-hook.js`, `hosting-save.js`, `hosting-setup.js`, `hosting-pipeline.js`, `hosting-run.js`: pass the order from the one read of the file to `seoName` (a `nameOrder` of the caller wins; still one `getText` call).
4. `images-screen.js`: the row "Order of picture names" gets a new `use` word `name`.
5. Tests: new `hosting-name-order-save.test.ts` (42 cases); `images-screen.test.ts` changed to the new truth.
6. Ten deliberate mistakes.
7. Version, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With a custom `nameOrder` in the file the Save writes the picture under the name that order gives; with every other text the Save works as before.
- No token or address is shown in any message.
