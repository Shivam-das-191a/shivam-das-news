## Goal
When `site/config/images.json` has `"askFirst": true`, the Save of the editor does not host any outside picture by itself: each one waits for the writer to confirm the rights. With `false`, a wrong value, a missing or a broken file nothing changes.

## Why it matters
The setting exists since Part 7m and the screen shows it, but nothing used it. Now the owner can choose "ask first" with no code change and no new secret. The shipped value is `false`, so today nothing changes.

## Steps
1. `images-setting.js`: `hostingSettingsFromText` adds `askFirst: true` to its answer only for the real value `true`.
2. `hosting-hook.js`, `hosting-save.js`, `hosting-setup.js`: take `askFirst` from the same one read (a caller value wins) and set `deps.askAll = true` only for the value `true`.
3. `hosting-pipeline.js`, `hosting-run.js`: pass `askAll` on.
4. `hosted-meta.js`, `hosting-plan.js`: with `askAll` a picture that would be fetched is `needs_confirm` (marked `askFirst`); reuse, refused and confirmed pictures are decided as before.
5. `hosting-run.js`: new `ASK_FIRST_TEXT` for pictures that wait only because of ask first.
6. `images-screen.js`: the row "How it starts" gets a new `use` word `askFirst`.
7. Tests: new `hosting-ask-first-save.test.ts` (51 cases); `images-screen.test.ts` changed to the new truth.
8. Seventeen deliberate mistakes.
9. Version, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `"askFirst": true` the Save makes no fetch and no picture commit; after the writer confirms an address (or its website) that picture is hosted; with every other value the Save works as before.
- No token or address is shown in any message.
