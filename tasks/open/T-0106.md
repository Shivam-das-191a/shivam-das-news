## Goal
The build stops when a built page has an empty heading, and it warns (does not stop) when headings come before the h1 or when a level is skipped after the h1 (an h3 straight after the h1, an h4 straight after an h2).

## Why it matters
POLISH (Accessibility) asks for a clear headline hierarchy. A screen reader user moves through a page by its headings; an empty heading is read as "heading" and nothing else, and a skipped level makes the page outline wrong.

## Steps
1. New `heading-order-lib.mjs` with `checkHeadingOrder`.
2. `validate-html.mjs`: call it for every built page.
3. New test `heading-order.test.ts`.
4. Look at the real built pages first (all headings of today's 17 pages), then build once more in a throw away copy with one published post, then run deliberate mistakes, one at a time.
5. Version 0.101.109, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- An empty heading fails the gate; headings in order pass; headings before the h1 and a skipped level only warn.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card).
- Check: `npm test`: 198 files and 4216 tests passed (before: 197 and 4189). `npm run build` ended with `Validation passed.` on today's real build. `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`.
- Real pages today: all 17 built pages start with two `h3` headings of the menu drawer ("Categories", "Colour style") before the h1, so each gives one warning. This is the reason why the rule is a warning and not an error: it would stop every build today.
- Throw away copy with one published post (made in `/tmp`, not in the ZIP): the pages of the category, the tag and the author give `h3` (the post card) straight after the `h1`, one warning each; the build still passed. An error rule would have stopped the first real publish.
- Deliberate mistakes: twenty-four made one at a time in the library. Twenty-two were caught at once; two were NOT (a tag such as `h3x` read as a heading; and the `hidden` attribute without a value was not seen, found while writing the tests); test lines were added and all twenty-four are now caught.
