## Goal
An `img` inside the article text whose `src` is a hosted picture with copies gets `srcset` and `sizes`, like the picture at the top of the article. Every other tag stays exactly as it was.

## Why it matters
Most pictures of a long story sit in the text, so phones now load the small copy there too.

## Steps
1. Read `picture-set.ts`, `picture.ts` and the article page (`plan.html` is the text with the auto links).
2. `picture-set.ts`: `SIZES.body` and `withPictureSets(html, map, sizes, exists?)`: rewrites each `<img>` whose `src` has a set; leaves tags that already have `srcset` or `sizes`.
3. `picture.ts`: `bodySets(html)` bound to `config/media.json` with the file check.
4. The article page: `bodyHtml = plan.html ? bodySets(plan.html) : plan.html` (the fallback `<Content />` is kept).
5. Tests, a real build with a temporary picture in the text, then the version, changelog and documents.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A text picture with `variants` and a stored `width` gets `srcset` and `sizes` right after `src`; a picture with no copy, an outside picture, a tag that already has `srcset` or `sizes`, and text that only shows a tag (escaped) are unchanged.
- Nothing changes on the live site until copies are on and a new picture is hosted.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 164 files and 3409 tests passed, build pass, content pass, tasks pass (64 cards).
- Real build with a temporary picture in the text: the expected `srcset` and `sizes` were written; an unknown picture in the same text was unchanged (temporary files removed).
- Not verified live: no real hosted picture, browser, Worker or GitHub token.

## If it goes wrong
In the article page put back `const bodyHtml = plan.html;` (or the files of v0.101.66). The text then has no srcset, as before.
