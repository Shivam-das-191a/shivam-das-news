## Goal
The build stops on a `<picture>` with no `<img>`, with more than one `<img>`, with a `<source>` after the `<img>` or with a `<source>` that has no `srcset`; it warns on a `<source>` with neither type nor media, a type that is not an image type and an empty media.

## Why it matters
A `<picture>` with no `<img>` draws nothing and has no alt text; a `<source>` after the `<img>` is ignored by the browser; a `<source>` with only a `src` gives the browser nothing to load. The pictures of this site use `<img srcset>`, but an HTML block pasted by hand (PLAN 37) or an imported Blogger post (PLAN 36) can carry a `<picture>`, and the dashboard preview shows nothing wrong.

## Steps
1. New `site/scripts/picture-check-lib.mjs` with `checkPicture(html)` (one pass over the picture, source and img tags; comments, script, style and template skipped; a source outside a picture is left to other checks).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `picture-check.test.ts` (40 cases, with a fake dist folder run of the real gate and a read of the base layout and the post card).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.143, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.
