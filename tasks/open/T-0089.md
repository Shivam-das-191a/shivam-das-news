## Goal
When `site/config/images.json` says `"enabled": false`, the Save of the editor does not host pictures: it goes on as before and the post keeps its outside pictures. With `true`, with no file, or with a broken file, nothing changes.

## Why it matters
The switch exists since Part 7p, but nothing read it. Now the owner has a real off switch for picture hosting that needs no code change and no new secret. It is the first setting after `quality` that the editor obeys. It needs no decision: the shipped value is `true`, so today nothing changes.

## Steps
1. `images-setting.js`: add `hostingSettingsFromText` and `readImagesForSave` (one read that gives `{ on, quality }`). Only a real boolean `false` gives `on: false`; any wrong or missing value, and any read error, gives `on: true`.
2. `hosting-hook.js`: `runHostingSave` uses the new read in place of `readImagesQuality` (still one `getText` call, still only when hosting is set up and the caller gave no `quality`). `on: false` returns `{ action: 'normal', reason: 'off', message: '' }` before any picture is fetched.
3. `images-screen.js`: the row "Picture hosting" now says that the Save uses it (a new `use` word, `save`); the help sentence says that Off keeps the pictures where they are.
4. Tests: new `hosting-switch-save.test.ts` (31 tests); two older tests that looked for the old call or the old `use` word are changed (`hosting-quality-save.test.ts`, `images-screen.test.ts`).
5. Nine deliberate mistakes.
6. Version, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `"enabled": false` the Save makes no fetch and no picture commit; with every other text the Save works as before.
- No token or address is shown in any message.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 182 files and 3716 passed (before: 181 files and 3685), build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (89 cards). The budget warning is the old one (CHANGELOG, INCOMPLETE; decision 43).
- Two older tests failed at first, as expected: one looked for the text of the old call `readImagesQuality(rest.gh, rest.cfg)`, one required the `enabled` row to be "not used yet". Both were changed to the new truth; the code was not changed to fit them.
- Deliberate mistakes: nine made one at a time (a missing value counted as off, a loose `==` that makes `0` mean off, the off switch ignored, off giving `stop`, a read error meaning off, the file read when hosting is not set up, the file read when the caller gave a quality, a message on the off outcome, the quality lost). All nine were caught at once. The files were put back after each and the tests passed again.
- Not verified live: no GitHub run yet, and the switch has not been tried in the real dashboard.

## If it goes wrong
Put back `site/public/admin/js/hosting-hook.js` of v0.101.91 (it calls `readImagesQuality` again). The new functions in `images-setting.js` can stay; nothing else uses them. Or set `"enabled": true` in `site/config/images.json`.
