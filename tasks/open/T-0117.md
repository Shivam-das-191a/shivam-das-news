## Goal
The build stops when an id on a built page is empty, has a space in it or is used twice, and warns when an in-page link or an `aria-controls` points to an id that is not on the page.

## Why it matters
The skip link, labels and the menu buttons find their target by id. With a repeated id the browser picks the first one, so a screen reader user can land on the wrong element, and a broken in-page link does nothing. A post body written by the owner can bring a repeated id (for example two headings with the same id).

## Steps
1. New `site/scripts/ids-lib.mjs` with `checkIds(html)`.
2. `site/scripts/validate-html.mjs`: run it on every built page.
3. New test `ids.test.ts` (30 cases, with a fake dist folder run of the real gate and a read of the real template).
4. Run the gate on today's real build (all 17 pages: 113 ids and 17 in-page links read, no message), then on throw away copies with the real build broken.
5. Version 0.101.119, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- An empty id, an id with a space and a repeated id fail the gate.
- An in-page link or `aria-controls` to a missing id only warns.
