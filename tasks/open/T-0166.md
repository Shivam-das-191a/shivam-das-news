## Goal
The build warns when the text of a built page repeats a word of 3 or more letters twice in a row ("the the"), and never stops the build for it.

## Why it matters
A doubled word is the most common typing slip in a news story. A reader sees it at once and trusts the site a little less. A post imported from Blogger or typed fast often has one, and nothing in the build read the text for it.

## Steps
1. New `site/scripts/doubled-check-lib.mjs` with `checkDoubledWords(html)` (reads the text of the body; head, comments, script, style, template, textarea, pre, code, kbd, samp, svg, noscript and select skipped; one message per page with a count and the first example; no errors).
2. A block tag and a character reference end the run, so two neighbouring list items or a word on each side of a dash never count. `had had` and `that that` are allowed. A first word with a mark glued to its end ("the, the", "no. No") is a real break.
3. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
4. New test `doubled-check.test.ts` (64 cases, with a fake dist folder run of the real gate).
5. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with a doubled word added.
6. Version 0.101.168, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A page with `<p>The council voted on the the new budget.</p>` gives a warning that names the page; the build still passes.
- `had had`, `that that`, `the, the`, `no. No`, two neighbouring list items and text inside `pre` or `code` pass with no message.
