## Goal
The build stops when `loading`, `decoding`, `fetchpriority`, `referrerpolicy`, `crossorigin`, a form `method` or `enctype`, or the `type` of an `<ol>` holds a value that is not one of the real choices; it warns on `referrerpolicy="unsafe-url"`.

## Why it matters
A browser never reports a typo such as `loading="laz"` or `fetchpriority="hihg"`: it silently uses its default, so a picture meant to load late loads at once and the hero picture loses its priority. The speed rules of POLISH depend on these two attributes. A form `method="put"` becomes a GET form without a word. Pictures, frames and links written by hand in a post (PLAN 37) can carry these attributes.

## Steps
1. New `site/scripts/attr-values-lib.mjs` with `checkAttrValues(html)`.
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `attr-values.test.ts` (30 cases, with a fake dist folder run of the real gate and a read of the real templates).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with a bad value added.
5. Version 0.101.129, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

- `loading="laz"` and `<form method="put">` fail the gate.

- Throw away copies of the real build in `/tmp` (not in the ZIP): see the CHANGELOG entry of 0.101.129.
- Found and fixed while testing: the first version dropped the whole `<script>` element before reading, so the attributes of a script tag were never read; now only the text inside is dropped and the opening tag is kept. The same drop of a whole script element is used by the older checks of this kind; they do not read script attributes, so nothing changes for them.
