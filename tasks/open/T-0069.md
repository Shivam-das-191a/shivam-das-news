## Goal
`site/config/images.json` gets an `allowHosts` list (shipped empty). A picture in the text of a published or scheduled post from a listed website counts as our own: no outside-picture warning, and no error under `hardBlock`.

## Why it matters
When the owner later keeps pictures on their own picture address (for example `media.yourdomain.com`, the R2 option of decision 15), the check would count them as outside pictures. The allow list tells the check which websites are the owner's own. It ships empty, so nothing changes today.

## Steps
1. `config/images.json`: add `"allowHosts": []`.
2. `validate-content-lib.mjs`: `checkPost` option `allowHosts`, `hostListed` (with `hostBlocked` as the same function), `checkImagesConfig` for both lists and for a name in both.
3. `validate-content.mjs`: read the list and pass it on.
4. Tests (7 new cases, one runs the script with an empty list, an allowed host and a bad entry), then five deliberate mistakes.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With `allowHosts` empty or missing: the same result as v0.101.71. With a listed website: no warning for its pictures, a warning (or an error under `hardBlock`) for other outside pictures. A name in both lists: a config error, and the block list wins.
- A draft is never checked. The shipped file has an empty allow list.
