## Goal
The build warns about an empty paragraph, list item, quote or caption and about two or more `&nbsp;` in a row, and never stops the build for them.

## Why it matters
An imported Blogger post and a pasted block often hold `<p>&nbsp;</p>` or `<p></p>` as a blank line and a row of `&nbsp;` as an indent. A screen reader reads an empty paragraph as a pause, Google sees a paragraph with no words, and the spacing cannot be set in CSS. Nothing in the build read these (`break-check-lib.mjs` reads only `<br>`).

## Steps
1. New `site/scripts/blank-check-lib.mjs` with `checkBlanks(html)` (comments and script, style, template, textarea, pre, svg and noscript blocks skipped; one message per kind with a count; no errors).
2. An empty box that has a `role`, `aria-live`, `id` or `data-` attribute is skipped, because a script fills it later.
3. `site/scripts/validate-html.mjs`: import it, run it on every built page, name it in the first comment line.
4. New test `blank-check.test.ts` (48 cases, with a fake dist folder run of the real gate).
5. Run the whole test suite and the real build, then the gate on a throw away copy of the real build with bad boxes added.
6. Version 0.101.166, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A page with `<p>&nbsp;</p>` gives a warning that names the page; the build still passes.
- `<p role="status"></p>`, a paragraph with a picture, one single `&nbsp;` and an empty table cell pass with no message.
