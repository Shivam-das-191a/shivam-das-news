## Goal
The build stops when a built page holds a list item, description term, option, figure caption, legend, summary, source or track outside the parent tag HTML names for it; it warns on a list with a direct child that is not an li, a dl with a stray child, a details with no summary and a fieldset with no legend.

## Why it matters
A browser does not repair an `<li>` with no list around it or a `<figcaption>` with no figure: it shows them as they are, and a screen reader does not say "list of 5 items" or "caption". A post written by hand (PLAN 37) or an old Blogger post (PLAN 11) can carry such lines, and the owner cannot see the fault in the dashboard preview.

## Steps
1. New `site/scripts/parent-check-lib.mjs` with `checkParents(html)` (a small tag stack; the end tags HTML lets a writer leave out are understood).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `parent-check.test.ts` (53 cases, with a fake dist folder run of the real gate and a read of the real base layout and seven real components).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.136, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A loose `<li>` and a loose `<figcaption>` fail the gate.
- A `<ul>` with a direct `<div>` and a `<details>` with no `<summary>` only warn.
