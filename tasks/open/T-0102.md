## Goal
The build stops when the final style of the site has no print rule, no visible focus ring, or uses motion without a reduced motion rule.

## Why it matters
POLISH lists a print stylesheet, a visible focus ring and "respect prefers-reduced-motion". The style does it today, but nothing kept it that way when someone edits `global.css`.

## Steps
1. New `css-polish-lib.mjs` with `checkCssPolish`.
2. `validate-html.mjs`: after the pages are read, check the collected style text (style blocks and css files) when at least one page was built.
3. New test `css-polish.test.ts`; the fake pages of the four older gate tests get a small base style (print rule and focus ring).
4. Deliberate mistakes, one at a time.
5. Version 0.101.105, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A style without a print rule, without a focus ring, or with motion and no reduced motion rule fails the gate; a good style passes; a site with no style at all fails.

## Evidence
- Files changed: the paths of this card (new files: the library, the test and this card).
- Check: `npm test`: 194 files and 4100 tests passed (before: 193 and 4079). `npm run build` ended with `Validation passed.` on today's real style (the real style already has the print rule, the focus ring and the reduced motion rule).
- Deliberate mistakes: fourteen made one at a time. Thirteen were caught at once; "outline any rule" (a property that only ends like outline counted as a ring) was NOT caught, so one test was added and it was caught.
- Not verified live: no GitHub run of the validate workflow yet.

## If it goes wrong
Put back `validate-html.mjs` of v0.101.104 and delete the library and the test.

## Stop and ask the owner if
- The cases in `AI_START_HERE.md` Section 4.
- A real build fails the new gate and the fix would be to weaken a rule.
