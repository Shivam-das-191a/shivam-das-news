## Goal
An admin can change the picture settings on the Picture settings screen and press Save picture settings: `site/config/images.json` is written to GitHub in one commit, only when every value is right.

## Why it matters
Until now the owner had to edit `config/images.json` by hand. The form, the checks and the save function all exist (Parts 7u, 7v, 7ac); this part joins them with one button.

## Steps
1. `app.js`, `imagesView`: remember the text the file held when the page opened (`loaded`, or `null` when there was no file); add the button `Save picture settings` under the form (disabled while a value is wrong); on click call `saveImagesSettings` with the checked values and `{ loadedText: loaded }`; show a green message after a save or a red fixed sentence on a failure; draw the screen again after a save so it shows the new file.
2. `images-form-screen.js`: the first sentence now tells the person to press Save (it said that saving was not built yet). The form itself still has no button.
3. `images-save.js`: comment lines only.
4. Tests: `admin-images-form.test.ts` (18 new cases with the real dashboard in jsdom and a fake GitHub that records every PUT), `images-form-screen.test.ts` and `images-save.test.ts` (changed to the new truth).
5. Deliberate mistakes, one at a time.
6. Version 0.101.99, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A good change makes exactly one PUT to `site/config/images.json` with the sha just read and the message `admin: picture settings`; a wrong value (button disabled), a file changed by someone else, a GitHub refusal or no change at all makes no commit and shows a plain sentence; no token or GitHub text appears on the screen.
- An editor does not see the screen or the button.
