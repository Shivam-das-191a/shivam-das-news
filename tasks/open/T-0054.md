## Goal
A picture whose alt text was written for the writer (`autoAlt: true` in `config/media.json`, made by auto image hosting) is marked on the Files screen until the writer has read it: a small mark on the tile, a count in the count line, and a note in the editor. Pressing Save details clears the mark.

## Why it matters
PLAN 34.5 says an automatic alt text is "marked for review". Until now the mark was stored but never shown, so a writer could not see which alt texts still need a human look.

## Steps
1. Read `files-screen.js`, `autoAltFiles` in `hosted-meta.js`, `mergeMedia` in `media-meta.js` and `onSave` in `app.js`.
2. In `files-screen.js`: the mark on the tile, ", N to review" in the count line (only when N is above 0), the note in the editor (only for a role that can edit), and `autoAlt: null` sent to `onSave` only for a marked file. `app.js` is NOT changed: its `onSave` already gives the fields to `mergeMedia`, which drops a null key.
3. Two small rules at the end of `admin.css` (colour variables only).
4. Write `site/tests/unit/admin-files-review.test.ts` (16 tests).
5. Make deliberate mistakes in `files-screen.js` and see the tests fail.
6. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes (all older tests unchanged).
- A file with no mark behaves exactly as before: the count line is the old text and `onSave` gets exactly `alt`, `caption`, `credit`.
- A marked file shows the mark, the count and the note; Save clears the mark and keeps the alt text and the other stored keys; a failed Save or a red error keeps the mark.
