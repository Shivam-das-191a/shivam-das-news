## Goal
When `site/config/images.json` has websites in `askHosts`, the Save of the editor does not host pictures from those websites: they wait for the writer to confirm the rights. With an empty, missing, wrong or broken list nothing changes.

## Why it matters
The setting exists since Part 7a and the screen shows it, but nothing used it. Now the owner can add a website that must ask first (a news agency, a stock site) with no code change and no new secret. The shipped list is empty, so today nothing changes.

## Steps
1. `images-setting.js`: add `customAskHosts` (the valid website names, or `undefined`); `hostingSettingsFromText` adds `askHosts` to its answer only when there is a valid name.
2. `hosting-hook.js`: take `askHosts` from the same one read (a list of the caller wins) and give it to `startHostingSave`.
3. `hosting-save.js`: give `askHosts` to `hostingSetup`.
4. `hosting-setup.js`: add the websites to the agency list (the dashboard list, or `DEFAULT_AGENCY_HOSTS`), never remove one, no repeat.
5. `images-screen.js`: the row "Websites that ask first" gets a new `use` word `ask`.
6. Tests: new `hosting-ask-hosts-save.test.ts` (34 cases); `images-screen.test.ts` changed to the new truth.
7. Ten deliberate mistakes.
8. Version, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- With a website in `askHosts` the Save makes no fetch and no picture commit for that website (and its sub names); with every other text the Save works as before.
- No token or address is shown in any message.

## Evidence
- Files changed: the paths of this card.
- Check: `npm run preflight` ended with `PREFLIGHT PASS (warnings: budgets)`: tests 184 files and 3792 passed (before: 183 files and 3758), build pass, content pass (1 post, 12 pages, 0 warnings), tasks pass (91 cards). The budget warning is the old one (CHANGELOG, INCOMPLETE; decision 43).

## If it goes wrong
Put back the four code files of v0.101.93. Or set `"askHosts": []` in `site/config/images.json`.
