## Goal
The dashboard code can read every setting of `config/images.json` in one careful step (`readImagesSettings`), as Part 7j did for `quality` only. Nothing calls it yet.

## Why it matters
Parts 7a to 7p added eleven settings to the file, but the dashboard reads only `quality`. Before any screen or any code uses the others, one reader must give each of them a safe value, so a bad or missing value never breaks the Save.

## Steps
1. `images-setting.js`: add `NAME_SOURCES`, `HOST_NAME`, `imagesDefaults`, `imagesSettingsOf`, `imagesSettingsFromText`, `readImagesSettings`. The old functions are not changed.
2. `images-settings-all.test.ts` (13 tests): the defaults equal the shipped file, the two copies of the naming words and the website name rule equal the ones of the build script, each setting is checked alone, bad list names are dropped, the naming order is taken whole or not at all, nothing throws, the input is never changed.
3. Five deliberate mistakes.
4. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- The shipped file read by `imagesSettingsOf` comes back equal; a bad value gives its shipped value and does not change the other settings.
