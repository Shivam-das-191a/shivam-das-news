## Goal
`site/public/admin/js/hosting-pipeline.js` has `savePostWithHosting(post, deps)` and `plainMessage(e)`: the one function that reads `config/media.json`, runs `hostPost`, builds the result list and makes ONE commit (or only previews). It never throws; it answers `{ ok, status, message, run, list, commit, next }`. No screen.

## Why it matters
The parts so far (`hostPost`, the result list, the commit) are separate. Without one function that joins them in the right order, the screen would have to do it, and a mistake there could lose a media row, save a post that points at a picture that is not there, or download pictures for a save that cannot be written. Nothing calls it yet, so the live site and the dashboard do not change.

## Steps
1. Read `hosting-run.js`, `hosting-result.js`, `hosting-commit.js` and `github.js` (`getText`, `commitFiles`).
2. Write `hosting-pipeline.js`: `savePostWithHosting`, `plainMessage`, `MEDIA_DIR`.
3. Write `site/tests/unit/hosting-pipeline.test.ts`: the save, the small cases, preview, the setup checks, the media file, a save made by someone else in between, a failed commit, Retry and Confirm through two saves, bad input, and the real GitHub client behind a fake network.
4. Make deliberate mistakes and see the tests fail; close the gaps.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- The setup is checked before any download; the media file is read before the run and again before the commit, and a save made by someone else in between is never lost.
- A failed commit changes nothing and `next` carries the post as it was; no token is in any message; a preview writes nothing.
- It never throws, whatever it is given.
