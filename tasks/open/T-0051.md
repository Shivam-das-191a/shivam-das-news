## Goal
`site/public/admin/js/hosting-hook.js` has `runHostingSave({ cfg, gh, next, body, orig, newPath, tree?, canEdit?, dryRun?, fetch?, optimizeDeps?, mount?, onSaved? })`: it runs the pictures flow and answers one of three actions for Save: `normal` (Save goes on as before), `saved` (the flow already wrote the post, Save must not write it again) or `stop` (nothing was written, Save stops).

## Why it matters
The hook in `save()` of `app.js` cannot be tested without a browser, so every decision it needs is made here by plain functions and tested: when the normal Save still writes the post, when it must not (the commit of the flow already holds the post file and the old file sha would be stale), what the editor shows after a Retry, and the new `orig` after a hosted save. Nothing calls it yet, so the live site and the dashboard do not change.

## Done when
- `npm test`, `npm run tasks:check`, `npm run check:content` and `npm run build` pass; older tests pass unchanged.
- Off, no outside picture, archived, a moved post and a setup problem each give `normal` and make no Worker call and no commit.
- A hosted picture gives `saved` after exactly one commit that holds the post file; a failed commit gives `stop` and no token in any text.
- `onSaved` is called after every run that made a commit, also after a later Retry; the editor's `next` and `orig` are never changed; `app.js` and `main.js` do not import the file yet.
