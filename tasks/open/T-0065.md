## Goal
`npm run check:content` (and so `preflight` and the validate workflow) prints a warning for every published or scheduled post whose text still shows a picture from another website. It never fails the check.

## Why it matters
PLAN 34.9 says the build gate lists posts that still have outside pictures. A picture on another website can vanish, is slow, and may not be ours to show.

## Steps
1. Read `hotlink.js` (`findExternal`) and `checkPost` in `validate-content-lib.mjs` (the front matter `image` and `ogImage` already warn).
2. `checkPost` gets an optional `ownHosts`; for status `published` or `scheduled` it calls `findExternal({ body }, ownHosts)` and adds ONE warning: the count and the first address.
3. `validate-content.mjs` passes the host of `SITE_URL` (when set) as `ownHosts`, so a full address of our own picture is not counted.
4. Tests (6 new cases, one runs the script), then five deliberate mistakes.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A published or scheduled post with outside pictures in the text gives one `WARN` line; a draft, an archived post, our own host, relative addresses, `data:` pictures and code give none; the last line is still `CONTENT PASS`.
- The shipped site (one draft post) gives no new warning.
