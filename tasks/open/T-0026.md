## Goal
The caption, credit and alt text that the owner saves on the Files screen appear on the public article, the home page and the post cards.

## Why it matters
Part 7b stores these details but the site ignored them, so typing them changed nothing for readers.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 33.3 and the rules of Part 7a.
2. Write the pure rules in `src/lib/media-alt.ts` and the two helpers in `src/lib/picture.ts`.
3. Use the helpers in the article page, `PostCard.astro` and the home page. The post's own `imageAlt` and `imageCredit` still win.
4. Write the tests, make deliberate mistakes, run the whole suite and a real build with temporary posts, then remove the temporary files.
5. Bump the version, write the changelog, update `CODING_PLAN.md` and `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- In a real build with a temporary entry in `config/media.json`, the article shows `Caption &middot; Credit` under the big picture, the post alt text wins over the stored one, the post credit wins over the stored credit, and the home page and cards carry the alt text.
- With an empty `config/media.json` the pages are the same as before.

## Evidence
- Tests: before this change `Test Files 127 passed (127), Tests 2373 passed (2373)`; after it `Test Files 128 passed (128), Tests 2386 passed (2386)`; 13 new tests in `site/tests/unit/media-alt.test.ts`.
- Real build with two temporary posts: article 1 gave `alt="Post own alt"`, `<figcaption>Stored caption &middot; Stored credit</figcaption>` and `og:image:alt` "Post own alt"; article 2 gave `<figcaption>Stored caption &middot; Post credit</figcaption>`; the home page and the cards carried the alt text. Temporary posts, picture and entry were removed; `config/media.json` is `{}` again.
- Deliberate mistakes: post alt not winning, `..` allowed, post credit not winning and the query not removed were each caught; removing the own-key check is not visible from outside (every key starts with `/media/`) and stays as a safety net. One real bug was found by the tests and fixed: a number in a stored field was turned into text.
- Preflight: see the line pasted in the Log below.
- Files changed: see the changelog entry of 0.101.29; every file is inside `paths`.
- Not verified live: not opened on the live site (zip delivery).

## If it goes wrong
Revert the commit; Cloudflare Pages, roll back to the previous deployment. Without the new files the pages read `imageAlt` and `imageCredit` as before; an empty `config/media.json` changes nothing on the site.
