## Goal
Replacing a picture in the Files screen (same address, new bytes) also removes its smaller copies (`name.480w.webp`) and the `variants` note, all in the same ONE commit. A picture with copies can be replaced again (the lock of 4c-4a is lifted).

## Why it matters
The address stays the same, so a copy left behind would still show the OLD picture to readers once `srcset` is on, and a note that names copies that do not exist would be a false fact. Nothing here makes a copy: the dashboard has no `makeVariants` yet. The copies come back when copies are switched on (a later part).

## Steps
1. Read `app.js` `onReplace`, `files-screen.js` `replaceBox`, `hosting-srcset.js` (`variantsOnList`) and `media-meta.js` (`replaceCheck`).
2. New `file-replace.js`: `planReplace(path, bytes, { sitePaths, pub })` (the new bytes first, then each existing copy as a delete; plain sentences for a path that is not a picture or is already gone) and `mapWithoutVariants(map, path)`.
3. `app.js` `onReplace`: use `planReplace` for the commit list and `mapWithoutVariants` for `config/media.json`; the message ends with `and remove N old smaller copies`; the handler returns the new map and the removed copies. Role check, `replaceCheck` and the fresh tree read stay first.
4. `files-screen.js`: the Replace box is no longer locked; the question names the copies and says why they go; the answer names them; the screen's own list and the hidden count follow. The helper `copiesNote` is gone (nothing is locked now).
5. Tests: new `file-replace.test.ts` and `admin-file-replace-copies.test.ts` (the real dashboard with a fake GitHub); the old "locked" tests of `admin-files-copies.test.ts` are replaced; one source guard in `admin-file-replace.test.ts`; the import guard in `hosting-srcset.test.ts` allows `file-replace.js`.
6. Make deliberate mistakes and see the tests fail.
7. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A replace of a picture with two copies makes ONE commit: the new bytes at the same path, both copies deleted, `config/media.json` without the `variants` note; the message says "and remove 2 old smaller copies".
- A replace of a picture without copies is exactly as before (one file in the commit, no write of `config/media.json`).
- A copy of another picture is never deleted. A copy is deleted only when it is in the list of files that exist now.
- The role check, the kind check (same kind of picture) and the size limit still come first.
- `makeVariants` is named in no dashboard file that switches copies on.
