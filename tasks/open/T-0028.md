## Goal
The owner opens a picture in Files and deletes it, but only when no post, page, author file or config file names it; the picture and its stored details leave in one commit.

## Why it matters
Old pictures pile up in the repository. A delete that could break a live post would be worse than no delete, so the plan (PLAN 33.3) says refuse while the file is used.

## Steps
1. Read `NEWS_WEBSITE_PLAN.md` 33.3 and 33.5.
2. Add `deleteCheck` and `removeMedia` to `media-meta.js`.
3. Add the Delete part to `files-screen.js` (refusal with the list, two taps, plain messages).
4. Add the right `media:delete` (admin, editor) to `roles.js`; wire `canDelete` and `onDelete` in `app.js` (role check, fresh read, use check, one commit).
5. Write the jsdom tests, make deliberate mistakes, run the whole suite and the build.
6. Bump the version, write the changelog, update `CODING_PLAN.md` and `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- In a jsdom test: a used file shows the refusal and the list and has no delete button; an unused file needs two taps; Cancel deletes nothing; Yes calls the delete once and the file leaves the grid; a failed delete changes nothing; a role without the right sees no button; `app.js` checks the role and the use again and makes one commit.
