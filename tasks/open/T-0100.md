## Goal
The build stops when a thumbnail does not say a 16:9 size, or when the style of `.thumb` loses `aspect-ratio: 16/9` or `object-fit: cover`.

## Why it matters
POLISH lists "Clean cards: image ratio 16:9 everywhere, no stretched images". The templates do it today, but nothing kept it that way when someone changes a template or the style.

## Steps
1. New `img-ratio-lib.mjs` with `checkThumbRatio` and `thumbCssProblem`.
2. `validate-html.mjs`: check every built page; collect the style text of the built pages and of the css files; check the style of `.thumb` when some page has a thumbnail.
3. New test `img-ratio.test.ts`; the fake article page of `img-priority.test.ts` gets the `.thumb` style (the first full run failed 2 of its tests, because that page has a thumbnail and no style).
4. Deliberate mistakes, one at a time.
5. Version 0.101.103, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- A built page with a thumbnail that is not 16:9 fails the gate; a build whose style of `.thumb` lost the ratio or the crop fails the gate; a good build passes; a build with no thumbnail is not asked for the style.
