## Goal
A dashboard screen module draws a form for the eleven picture settings (`imagesFormScreen`). While the person types it shows a plain sentence under each wrong value, what would change, and the text that would be written. It has no button and no save. Nothing calls it yet.

## Why it matters
Part 7t built the checks. This part puts them in front of the owner as a page, so the owner can try the form and see the result before any save exists. The save waits for decision 24 (the write mode).

## Steps
1. `images-form-screen.js`: one control for each setting (`data-key`), the list of errors (`aria-invalid` on the wrong box), the list of changes, the text of the new file, `read()`, `text()`, `update()`, an optional `onChange`. No button, no form tag, no fetch, no storage, no HTML building; only classes that `admin.css` already has.
2. `images-form-screen.test.ts` (27 tests): drawing and the start state, good edits, a wrong value and its fix, two wrong values, the switches and the storage, website lists, the naming order, the text passes the build check, unknown keys kept, text is never HTML, `onChange`, `update`, nothing leaves the page, the file itself.
3. Nine deliberate mistakes.
4. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.`
- The form shows eleven controls, one error sentence for each wrong value, and the text it shows passes `checkImagesConfig`.
- The page has no button, no link, no form tag, and sends nothing anywhere.
