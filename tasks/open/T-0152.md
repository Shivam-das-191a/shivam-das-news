## Goal
The build stops when a structured data block (`application/ld+json`) is not valid JSON, has a script type that is a typo of it, has an `@type` that is a typo of a real schema.org type, or has a `datePublished` or `dateModified` that is not a real ISO date; it warns on an empty block, a missing `@context` or `@type`, an HTML entity in a text and a few other small things.

## Why it matters
One comma too many or a type written `application/ld-json` makes search engines ignore the whole block (the NewsArticle, the breadcrumbs, the publisher) and no message reaches the owner. The build gate only checked that a block parses, and only when the script tag had no other attribute. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry these.

## Steps
1. New `site/scripts/jsonld-check-lib.mjs` with `checkJsonLd(html)` (comments and template blocks skipped; a block whose tag holds a template expression or `set:html` is not read).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page; the old `invalid JSON-LD` line is kept.
3. New test `jsonld-check.test.ts` (84 cases, with a fake dist folder run of the real gate and a read of the base layout, the search page and the 404 page).
4. The older test `img-priority.test.ts` wrote the fake dates `d`; change them to real ISO dates (the new check stopped them, which is right).
5. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
6. Version 0.101.154, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test` passes and `npm run build` ends with `Validation passed.` and no new message.
- A script type of `application/ld-json` fails the gate and names the page.
- An `&amp;` in a text only warns.
