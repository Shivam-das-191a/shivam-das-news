## Goal
The build stops when an `hreflang` of a link (`a`, `area`, `link`) or a `srclang` of a `track` is not a language code (`english`, `en_US`); it warns when an `hreflang` is empty or a subtitles track has no `srclang`.

## Why it matters
`<link rel="alternate" hreflang="english">` and `<a hreflang="en_US">` look right, but search engines ignore the alternate page and a browser cannot name the language of the link. A subtitles track with `srclang="french"` cannot be offered by its language. `lang-check-lib.mjs` leaves these two attributes out on purpose, so nothing else read them. Old Blogger posts (XML import) and a snippet pasted by hand (PLAN 37) can carry them.

## Steps
1. New `site/scripts/langtag-check-lib.mjs` with `checkLangTags(html)` (one pass over all tags; comments, script, style and template skipped; the language code rule is `isValidLang` of `lang-check-lib.mjs`).
2. `site/scripts/validate-html.mjs`: import it and run it on every built page.
3. New test `langtag-check.test.ts` (44 cases, with a fake dist folder run of the real gate and a read of the base layout, the footer and the post card).
4. Run the whole test suite and the real build, then the gate on throw away copies of the real build with bad markup added.
5. Version 0.101.150, changelog, `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.
