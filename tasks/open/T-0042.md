## Goal
`site/public/admin/js/hosting-optimize.js` has `optimizePicture(bytes, kind, deps)` and `makeOptimizer(deps)`: the function `optimize(bytes, kind)` that `hostPost` asks for. It makes a Blob of the right type, calls `prepareImage` (image.js) and returns `{ bytes, ext, width, height }`. For a GIF it reads the size from the header with `gifSize`.

## Why it matters
`hostPost` gets bytes from the images Worker, but `prepareImage` wants a File. Also `prepareImage` says `null` for the size of a GIF, and `recordHosted` refuses a row without a whole width and height: without this part every GIF would fail. Nothing calls it yet, so the live site and the dashboard do not change.

## Steps
1. Read `hosting-run.js` (how `optimize` is called), `image.js` (`prepareImage`), `hosted-meta.js` (`recordHosted`).
2. Write `hosting-optimize.js`: `KIND_TYPES`, `gifSize`, `optimizePicture`, `makeOptimizer`.
3. Write `site/tests/unit/hosting-optimize.test.ts`: the GIF header, every kind word, refusals, the real `prepareImage` behind a fake canvas, and runs inside `hostPost`.
4. Make deliberate mistakes and see the tests fail.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- Bytes and a kind word become a Blob of the right type; SVG, an unknown kind and empty bytes are refused before the browser is asked.
- A GIF keeps its bytes and gets its true width and height; width and height are always whole numbers above 0.
- An error of the browser goes up unchanged (`hostPost` says `optimize_failed`); a `jpg` answer is passed on (`hostPost` says `unsupported_format`).
