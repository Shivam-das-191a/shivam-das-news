## Goal
`site/public/admin/js/hosting-flow.js` has `hostingFlow({ post, deps, dryRun?, onResult?, onReplace?, canEdit? })`: it runs `savePostWithHosting`, draws the list with `hostingScreen`, and makes Retry and Confirm run the pipeline again. It answers `{ el, start, state }`. It does not fetch, read a token or touch GitHub by itself.

## Why it matters
The pipeline (3c-5) and the screen (3c-6) are separate. Without one object that joins them, the hook into Save would have to do it, and a mistake there could save from the wrong post after a failed commit, lose a confirmation, run two saves at once, or turn a preview into a real save. Nothing calls it yet, so the live site and the dashboard do not change.

## Steps
1. Read `hosting-pipeline.js`, `hosting-result.js` (`confirmFor`) and `hosting-screen.js`.
2. Write `hosting-flow.js`; add `say` to `hosting-screen.js`.
3. Write `site/tests/unit/hosting-flow.test.ts` (jsdom, a fake GitHub that remembers the media file) and the tests of `say`.
4. Make deliberate mistakes and see the tests fail; close the gaps.
5. Bump the version, write the changelog, update `CODING_PLAN.md`, `INCOMPLETE.md`, `UPDATE_NOTE.md`.

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- Only one run at a time; a failed commit leaves the next run on the post as it was; a confirmation is kept when the run after it fails.
- Only the value `true` makes a preview; a preview writes nothing.
- No token in any message; the editor's own post is never changed; bad input never throws.
