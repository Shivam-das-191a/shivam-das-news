## Goal
Changing the handle of a published post shows the 301 question: required and locked for a post live more than 24 hours, on by default and switchable for a younger post; the save obeys the answer.

## Why it matters
A changed address without a redirect loses the readers and the search ranking of the old address. The rule of LOGICS 21 and PLAN 33.2 is now in the editor.

## Steps
1. Read `LOGICS.md` Section 21 (`changeHandle`) and `NEWS_WEBSITE_PLAN.md` 33.2.
2. Add the question to `listing-box.js` using `changeHandle()` of `listing.js`.
3. Give `nextRedirects` an optional `keepOld` and pass the choice from `app.js` at Save.
4. Write the tests (pure redirect rule, the question in the box, the real editor) and break the code on purpose to prove they fail.
5. Bump the version, write the changelog, tick Part 3 in `CODING_PLAN.md`, update `INCOMPLETE.md` (`VERSIONING.md`).

## Done when
- `npm test`, `npm run build` and `npm run preflight` pass; older tests pass unchanged.
- An old live post cannot lose its redirect; a young live post can; a draft is never asked.
- The saved Markdown of a young post with the switch off has no redirect for the old address.

## If it goes wrong
Revert the commit; the editor returns to always keeping the old address.

## Stop and ask the owner if
- The repeated handle rule or the description limit must change (see the changelog of 0.101.18).
- The switch should apply to a handle change only (it now covers any URL change of a young post).
